# 기존 회귀 격리 실행 결과

검증일: 2026-10-10

## 결론

운영 DB, 실제 연락처, 실서비스 SDK를 사용하지 않고 발견된 **150개 체크를
모두 실행했다. 최신 증거 기준 140개 통과, 10개 실패**다. 체크 하나가 여러
테스트를 포함하므로 이 숫자를 단위 테스트 개수로 해석하면 안 된다.

실패를 허용 목록으로 통과시키거나 assertion을 제거하지 않았다.
**전체 회귀가 모두 통과한 상태는 아니다.** 남은 실패가 있는 전체 실행은
0이 아닌 종료 코드를 반환한다.

| 검사 | 결과 |
|---|---|
| Python 통합 수집 | 1,064개(기존 1,033개 + 공매 참고행 계약 31개), 239개 subtest 통과; 수집 오류·skip 없음 |
| 별도 건축정보 파서 단위 검사 | 12개 통과 |
| 격리 경계 자체 검사 | 7개 통과, HTTP·HTTPS의 준비 요청·리디렉션·경로 우회까지 확인 |
| 단독 `python tests/smoke_test.py` | 종료 코드 0 |
| 단독 `python tests/api_test.py` | 숙박·공매 참고행 검증 분리 후 종료 코드 0 |
| 기존 전용 실행기를 사용한 HS2 DB·브라우저 검사 | 실행한 체크 모두 통과 |
| 가상 공매 목록 화면 캡처 | 비어 있지 않은 50개 가상 원장 목록 확인 |

## 해결한 테스트 데이터·실행 환경 문제

- 한 지역만 있던 원장에 두 지역을 만들고, 이름으로 찾는 기존 표본에
  가상 주소·신고·중개·관심저장 데이터를 제공했다. 실제 원장은 복사하지 않았다.
- 운영 지문이 필요한 검사는 별도의 읽기 전용 가상 기준 DB로 연결했다.
- 공매 현재 회차, 상세 수집 표식, 목록 전용 이미지, 미연결 물건,
  예정 공매의 두 번째 페이지를 가상 원장으로 준비했다.
- 사진 URL 검증을 해제하지 않고 테스트 서버의 가상 HTTP 이미지를 사용했다.
  멤버십 화면의 계좌 설정도 실계좌가 아닌 가상 값으로 준비했다.
- 운영업체 변경 단위 검사에는 실제 인증 함수가 읽는 가상 승인행을 제공했다.
  변경·미존재·커밋 후 무효화 assertion은 유지했다.
- SDK 로드 콜백을 동기로 즉시 실행하던 모의 구현을 비동기 구현으로 고쳤다.
  이에 영향을 받았던 공매 건물 연결 브라우저 검사는 다시 통과했다.
- 순수 파서의 모의 응답 큐를 앱 백그라운드 작업이 소비하지 않도록 독립
  프로세스로 실행했다. 격리 경계 검사도 자신의 DB 소유권으로 독립 실행했다.
- 정리된 상위 환경에서도 Python 의존 경로를 보존했다. 상위 실행기의
  임시 산출물 경로가 DB 소유권 경로를 바꾸지 않도록 DB 생성 위치를 고정했다.
- 원본 비교에 필요한 읽기 전용 Git 명령은 허용하되 전송·변경 명령은 차단했다.
- 새 캡처는 배포·Git 제외 디렉터리에 저장한다. 초기 실행이 덮어쓴 원래
  PNG는 원본 바이트로 복원하고 해당 실행의 캡처는 별도 보존했다.
- 완료 검사의 필수 API 명령이 공매 참고행 계약 충돌로 거부되어 해당
  검증을 보완했다. 기존 숙박 행의 필수 컬럼·공개 지표·합계 검사는 유지하고,
  공매는 정확히 한 참고행·별도 필드·정수 건수·전체 참고수 일치를 검증한다.
  0건·비어 있지 않은 원장과 11가지 손상 계약을 별도 검사한다. 제품 응답을
  바꾸거나 누락 필드를 채워 통과시키지 않았다.
- 병합 후 실제 참고행에는 관리자 표의 호환용 중립 컬럼이 추가돼 있었다.
  현재 앱을 수정하지 않고 원래의 간결한 참고행과 완전한 호환 참고행만
  검증한다. 호환 컬럼은 `0`·`None`·`not_applicable`의 정해진 타입과 값만
  허용하며 부분 컬럼·알 수 없는 컬럼·실제 숙박 수치는 거부한다.
  새 프로세스에서 가상 관리자 로그인 후 **실제 끝점**을 조회하는 계약 사례와
  모든 호환 컬럼의 손상 사례를 추가했다. 완료 검사의 실패 로그도 보존했다.
- 최신 프로젝트와 합칠 때 기존 HTTPS owned origin, HS2 comparator DB,
  가상 표본의 기능을 보존했다. 이미 포함된 계층별 차단과 가상 SDK·이미지
  제공을 유지하며 HTTPS 준비 요청과 리디렉션도 별도 경계 검사로 확인했다.
  전체 실행기가 다른 전체 실행기·스키마 준비 도구를 다시 발견하는 재귀는
  차단했다. 검사 파일은 제외하지 않았다.
- 최신 화면의 캠핑 건물수 제목은 `건물수<small>(시설수)</small>`로 바뀌었다.
  해당 정적 검사는 두 줄 제목과 캠핑 시설 설명을 검증하도록 맞췄고,
  가로 넘침 방지 CSS 검사는 유지했다. 정리된 자식 프로세스의 `/proc` 조회
  경합은 실제 프로세스가 사라진 경우에만 정리 성공으로 판정한다.
- 최신 프로젝트에 포함된 운영자 사진 관리 기능은 재검사에서 통과했다.
  이전 실패 로그도 남겨 실제 기능 변경과 테스트 fixture 수정을 구분했다.

가드 없이 직접 실행하는 명령은 이 검증의 안전한 진입점이 아니다.

## 실행하지 않은 것

운영 DB 접근·운영 원장 복사·실제 이메일/SMS 발송·실서비스 SDK 연결·운영
수집·실제 PG/은행 결제·배포·Phase18 승인은 실행하지 않았다. 기존 수기
입금 상태 전이 검사는 가상 DB와 가상 계좌에서만 수행했다. 임시 앱 서버와
PostgreSQL은 각 실행 종료 시 정리했다. 제품 앱의 인증이나 운영 설정은
변경하지 않았다.
