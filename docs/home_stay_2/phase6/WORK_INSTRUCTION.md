# Work → Replit: 사용자 Phase 6 — 단기임대 매물등록

Phase 5의 현재 소스 전체 24개 등록검사 PASS·내부 Work 검토·immutable 완료 tag·
개발 브랜치 원격 일치/main 불변 확인 뒤 시작했다. 기존 native 계획/영수증은 유지한다.

## 원문 구현 경계

원문 6절·13절을 따른다. 주소/건물 선택 → 공간정보 → 사진 → 옵션 → 가격 →
예약규칙 → 공개설정 → 등록. 기존 회원·복수 사업장·주소 참조 계층을 재사용한다.
일반 건물을 숙박 master에 강제로 넣지 않는다. 건축물 용도만으로 후보/등록을 막지 않는다.
건축물 용도는 참고 정보이며 플랫폼이 법적 사용 가능성을 판정하는 게시 전 Gate를
추가하지 않는다. 등록정보·운영 책임 고지는 등록자/운영자에게 한다.

사업장 Mode 선택과 실제 건물의 등록권한을 동일시하지 않는다. actor·business·building
소유 경계, CSRF, 재검증/철회, 원본 보존, draft/edit/delete 상태를 실제 DB/API/UI로 검사한다.
가격/캘린더·전체 검색·예약/결제·실제 운영 연결은 후속 Phase와 승인 경계로 분리한다.
기존 제한공개 주소/건물명/사진/좌표 및 자동 건물값 보호를 우회하지 않는다.

## 현재 사용자 결정 필요 — P06-PUBLICATION-TIMING

원문은 등록 마지막 단계의 공개설정을 요구하지만 새 매물의 공개 시점은 정하지 않았다.
기존 P-PUBLICATION도 OPEN이다. 등록 완료와 소비자 공개를 같은 상태로 처리할지,
관리자의 등록권한/공개정보 확인을 별도 상태로 둘지에 따라 상태·알림·화면이 달라진다.
권한·공개정보 확인을 플랫폼의 건축물 용도/법적 사용 가능성 심사로 바꾸지 않는다.

이번 질문은 공개 시점/처리 흐름만 결정한다. full/연락처 공개, 권리 유효기간,
세금·부분 월·취소·재고·실제 배포/운영 권한까지 승인한 것으로 해석하지 않는다.
현재 acceptance는 미등록이며 Phase 6 구현/완료 PASS를 주장하지 않는다.
