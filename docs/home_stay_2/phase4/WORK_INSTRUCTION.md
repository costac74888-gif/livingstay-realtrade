# Work → Replit: 사용자 Phase 4

원문 20절 Phase 4 로그인/사용자·운영자 Mode 분리.
대응: AUTH-01 / S02-A01 / S02-A02. native 2를 자동 COMPLETE로 바꾸지 않는다.

## 지시

- 기존 `users`, `account_role_memberships`, `account_business_memberships`,
  카카오 provider ID 기반 로그인, 사업자 이메일 로그인, 승인 사업장 조회를 재사용.
- 신규 회원 DB/인증 공급자나 이메일만으로 자동 병합하는 로그인 구현 금지.
- 새 모드는 독립된 표시/선택 상태이며 법적 승인·매물 등록 권리를 새로 부여하지 않음.
- 사용자 계정 변경·로그아웃·멤버십 철회·이메일 재인증 만료 시 모드 권한 재검증.
- 미승인/타인/잘못된 사업장 선택 거절, CSRF·요청 크기·로그인 rate limit 적용.
- 비공개 개발 화면과 실제 callback/API를 구현. 현재 운영 앱에는 mount하지 않는다.
  실제 기존 인증 함수의 격리 실행과 fixture PostgreSQL, 실제 브라우저로 검증.
- 기존 관리자 세션, 회원·사업장 이력, 공개/제한공개, 원장·원래 route는 보존.
  테스트에서 실제 OAuth 요청·이메일·SMS·운영 DB 호출은 0회.

## 실제 acceptance

- P04-A01: callback 기반 mode API, 계정/사업장/세션/CSRF/실패/철회/만료 권한 검사.
- P04-A02: 원본 인증 함수 실행 + owned PostgreSQL의 로그인/복수 사업장/카카오
  state·실패·이메일 충돌/로그아웃 검증. 모의 SQL 성공만으로 대체하지 않는다.
- P04-A03: 원문/순서/기존 Phase 1~3 영수증·원래 검사·native 기준·운영 Gate 보존.
  부분/오래된/실패 검사, 미구현 기준, 원격 미확인을 완료로 처리하지 않는다.
- P04-A04: 실제 Chromium 화면의 이메일 로그인, 카카오 진입 링크,
  사업장 선택/전환, 오류/로그아웃/계정 재확인 및 PC/모바일 기본 접근성.
