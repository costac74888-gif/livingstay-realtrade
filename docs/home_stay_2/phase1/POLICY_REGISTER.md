# 미확정 사업정책 및 중단 조건

새 지시와 고정 명세의 숙박 1박·날짜별 / 비숙박 7일·주월 /
확정예약 가격 불변 / 기존 원장 보존은 충돌하지 않는다.
나머지는 설계에 빈 결정을 명시하며, 사업정책을 임의로 승인하지 않는다.

| 정책 ID | 상태 | 확정 전 차단할 후속 동작 |
| --- | --- | --- |
| P-CLASSIFICATION | OPEN | 최종 서비스 숙박 분류, 복합 건물/호실별 허가 범위. 미확인·상충을 자동 비숙박으로 분류하지 않음 |
| P-LEGAL | OPEN | 용도별 운영 적법성·전대 동의·도시민박 내국인 수용·신고/안전/보험. 후보/숙박분류만으로 공개·예약 승인 불가 |
| P-TIME | OPEN | 사업장 timezone 설정·날짜 입력/체크인 시각·연휴 정의와 갱신 출처. 로컬 날짜 계약과 별개로 운영 정책 승인 필요 |
| P-PERIOD | OPEN | 부분 주/월, 달력월/입실 기념일/고정일수, 윤년/말일·일할 계산·기간 요금 우선순위. 임의 30일/일할 계산 금지 |
| P-MONEY | OPEN | 세금/관리비/추가비/할인/보증금 포함·정밀도·반올림·표시/수납 구성. fixture의 explicit adjustments는 실제 정책 승인 아님 |
| P-CANCEL | OPEN | 취소·환불·중도퇴실·노쇼·분쟁/신고 및 정책 변경의 과거 예약 적용 범위. 실제 환불/원본 확정가격 수정 금지 |
| P-INVENTORY | OPEN | 건물전체/호실 중첩, 공유 pool 수량·hold 유효기간·외부 채널 동기화·경합 복구. prototype 동일 pool 검사는 예약 엔진 구현이 아님 |
| P-SETTLEMENT | OPEN | 수수료·정산주기·수취인/증빙/PG·대사. 실제 결제·환불·정산 미승인 |
| P-PUBLICATION | OPEN | 새 매물 승인/권리검증 유효기간·full 공개·연락처 공개·개별호실 공개 정책. 기존 권한/위치보호 무변경 |

OPEN은 명세·데이터 설계 단계에서 기록할 수 있지만, 정책에 의존하는 실제 서비스
구현/운영 승인으로 이어지지 않는다. prototype Terms.reviewed와 permit_verified는
명백한 인메모리 fixture로만 사용한다. 실제 owner approval이나 법적 확인값이 아니다.

이번 Phase 1 검증은 상충 분류·미확인 근거·미승인 월 정책·불완전 가격표를
ContractError로 차단하는지를 확인한다. 테스트/보존 위반, 명세의 확정 요구와
상충하는 결정이 발견되면 단계 완료/후속 진행을 중단한다.
OPEN 정책을 해결했다는 허위 PASS, 문서 존재만의 acceptance, 회귀 삭제/해시
기준 변경, skip을 통한 통과는 허용하지 않는다.

운영 migration / 실제 PG·결제·환불·정산 / 배포는 기존 NOT_APPROVED 게이트를
유지한다. request-approval 명령도 이번 범위에서 실행하지 않는다.
