# Work → Replit: 사용자 Phase 5

원문 8절, 20절의 PC 소비자 Main. native 11 일부에 대응한다.
Phase 4 완료·전체 소스 재검증·개발 원격 SHA 확인 후 시작했다.

## 구현 범위

- PC 좌측 단기임대 목록/상세 영역, 우측 기존 지도 엔진 영역.
- 검색 1행: 지역/건물/지하철 위치검색, 입실일, 퇴실일, 검색.
- 검색 2행: 가격, 방 수, 유형, 면적, 인원, 옵션, 즉시입주, 할인, 기타 필터.
- 매매/영업권 양도/공매를 소비자 핵심 상단 메뉴로 올리지 않는다.
- Phase 6 등록, 7 가격/캘린더, 8 실제 검색·Super Map, 9 상세·예약 패널의
  후속 범위를 Phase 5 완료라고 주장하지 않는다.
- 기존 제한공개/위치보호와 숙박·비숙박 체류/요금 차이를 그대로 유지한다.
- 실제 데이터/API·화면 상호작용·격리 PostgreSQL/Chromium·전체 등록 검사로
  acceptance를 정의한다. P05-A01~03을 현재 등록하고 실제 검사 결과로만 판정한다.

## 현재 기반의 명시적 한계

이 단계는 PC Main 기반이며 Phase 8 전체 검색 완료가 아니다. 기존 Phase 2 공개
view는 제한공개 ID·숙박분류·위치 비공개만 제공한다. 비공개 건물명/주소/사진/GPS나
자동 건물값을 새 검색 응답에 넣지 않는다. 상세 검색 조건은 2행 구조를 유지하되
공개 메타데이터 준비 전에는 사용 불가라고 표시한다. 지도는 기존 Kakao SDK의
초기화 인터페이스를 연결하고, 위치 비공개 대상에 새 좌표/마커를 만들지 않는다.
실제 SDK 왕복/전체 지도 레이어, 지역·건물·지하철 검색, 등록 메타데이터,
실시간 운영 요금은 Phase 6~8에 연결한다. 실패를 가짜 데이터/가짜 지도로 대체하지 않는다.

## 사전 검토에서 발견한 사업정책 Gate

원문 7절은 숙박 날짜별 1박 요금과 비숙박 운영자 설정 주·월 요금을 고정한다.
8절은 공통 가격 필터를 요구하지만, 필터값을 선택 기간의 총액으로 비교할지
숙박 1박/비숙박 주·월 단가로 비교할지는 지정하지 않는다.

이 선택은 검색 상태·필터 라벨·후속 견적 엔진과 검색 결과의 의미를 바꾼다.
기간을 임의로 30일로 환산하거나, 1박 단가와 1주/1월 단가를 같은 금액인 것처럼
비교하지 않는다. P-MONEY/P-PERIOD는 OPEN으로 보존하며 한 정책의 응답이
다른 미확정 세금·부분 기간·수납 정책까지 승인한 것으로 해석하지 않는다.

**정책 결정: RESOLVED — P05-PRICE-FILTER (2026-10-10)**

사용자가 **선택한 입·퇴실 기간의 총액 기준**을 선택했다.
가격 필터는 기간을 선택한 뒤 그 기간의 유효한 총액 견적으로만 비교한다.
입·퇴실 기간이 없거나 해당 기간 견적이 불완전하면 단가 환산/0원으로 대체하지 않는다.
가격 필터 라벨·API 조건·검사에도 selected_stay_total 기준을 명시한다.

Phase 5~18을 완료로 바꾸거나, 운영 승인 Gate를 자동으로 열지 않는다.
