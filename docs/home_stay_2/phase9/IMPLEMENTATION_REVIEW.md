# Phase 9 — 내부 Work 구현검토

상세와 견적 조건 확인은 원래 승인 원장·가격 엔진·FK-bound immutable snapshot을
재사용한다. Native S10-A01/S11-A02의 가격/공개 일치 근거를 보강하며 실제
예약 경쟁·확정은 Phase10에서 검증한다. 내부 검토이며 운영 승인이 아니다.

- 검색의 공개 ID로 상세·뒤로가기를 연결한다. 상세 직접 조회는 검색 첫60건
  제한을 우회하지 않고도 현재 승인/권한/공개 요약과 안전한 geometry를 별도로
  재확인하므로 뒤 페이지의 ID도 private lookup으로 처리하지 않는다.
- 동의한 운영자 입력의 방/면적/최소 체류/인원/옵션만 표시한다. 정확 명칭·주소·
  업로드한 비공개 사진·자동 건물 정보를 공개하지 않는다. 동의하지 않은 수용
  인원은 견적 성공/실패를 통한 추론도 차단한다.
- 선택한 기간·인원과 실제 일/주/입실기념일 월 가격 구성·필수비용 포함 확인을
  표시한다. 누락·0원·과대인원·부분 주월·막힌 날짜는 실패한다. 보증금/환불/
  세금 등 미설정 값을 0원이나 확정 정책으로 표시하지 않는다.
- 본인 로그인/소비자 모드/이메일 확인과 계정 활성·CSRF·명시적 견적 조건
  확인을 서버에서 요구한다. 요청은 strict body/schema와 현재 source version으로
  검증한다. 견적확인은 재고 hold·예약확정·계약·결제·정산이 아니다.
- 소비자별 request UUID와 transaction advisory lock으로 재전송·동시 요청을
  멱등 처리한다. 요청 내용이 달라지면 거부한다. 원래 불변 snapshot FK를
  저장하고 별도 append-only 본인 전용 receipt는 DB 시각 기준 10분만 유효하다.
- 다른 회원 조회·미확인 계정·만료·철회/권한 취소·변경된 요금/등록 revision/
  재고 비가용성은 다시 검사한다. 새 요금은 이미 저장된 snapshot을 변경하지 않는다.
- UI는 입력·매물·인원·source 변경·늦은 응답에 견적/동의를 즉시 폐기하고
  정상 서버 응답 뒤 receipt/만료를 표시한다. 새 조건은 새 request key를 쓰며,
  응답 불명확한 같은 조건만 기존 key로 retry한다.
- Native 매매/영업권/공매 카드에 단기임대 기간 가격 문구를 표시하지 않는다.
  Native 상세 기능·공매 3탭·기존 통계/본체 route는 제거하거나 변경하지 않는다.
