# Work → Replit: 사용자 Phase 9 — 매물 Detail + 예약 Panel

Phase8 전체 34개 PASS·내부 검토·immutable checkpoint·개발 commit/tag와
main 불변 확인 뒤 진행한다. 원문 사용자 단계 9와 Native S10-A01/S11-A02를
연결하며 실제 예약 재고/hold/확정은 사용자 단계 10이다.

실제 현재 승인 단기임대 공개 요약·유형·최소 체류·날짜·인원·운영자가 확인한
필수비용 포함 기간총액/일·주·월 구성·정책 버전을 상세와 예약 패널에서 일치시킨다.
제한공개 정확명칭/주소/사진/자동 건물정보는 유지하고 대략 위치만 표시한다.
가격·가용성·공개 source가 바뀌면 이전 견적을 폐기하여 0원·오래된 금액으로
다음 예약 단계에 들어갈 수 없게 한다. 입력·인원·로그인과 source fence를
서버에서도 검사한다.

권장 진행: 예약 전에 로그인한 소비자 모드·필수 조건 확인·CSRF·현재 source
재검증을 요구한다. 실제 원래 FK-bound immutable price snapshot과 연결되는
소비자 본인 전용, 유효기간 제한 견적확인 receipt를 저장한다. 이 receipt는
재고 hold·예약확정·계약·입금/카드결제·정산이 아니며 UI에서도 명확히 구분한다.
동일 요청 retry는 멱등 처리하고 다른 회원 receipt 조회·변조·취소/withdrawal/
revision 변경·만료 뒤 사용을 차단한다. Booking Engine이 후속에서 이 receipt와
현재 원장을 다시 확인한다.

가격 0/미확인 요금을 만들지 않는다. 아직 설정하지 않은 보증금·환불/세금 등은
‘결제 전 확인 필요’로 표시하고 0원·무료·확정 법정정책으로 표시하지 않는다.
서비스 기본 통화/시간대와 일/주/입실기념일 월 정책은 Phase7을 그대로 사용한다.

같은 source public ID로 검색→상세 이동/뒤로가기를 지원하며 다른 종류 상세는
예약 패널을 표시하지 않는다. Native 매매/영업권/공매 정보는 단기임대 총액으로
오해하게 표시하지 않고 기존 원래 상세 기능·공매 3탭을 제거하지 않는다.
실제 SDK·원래 회원 세션·live host mount는 통합 단계에서 연결하며 fixture 검사를
실서비스 검증으로 주장하지 않는다. production/실제 PG/publish Gate는 닫힌다.
