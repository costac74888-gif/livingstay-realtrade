# Work ↔ Replit 연속 진행 원칙

2026-10-10 사용자 최신 지시. 과거의 “Phase 3에서 중단” 및 “다음 Phase마다
별도 지시 필요” 제한은 해제한다. 완료된 Phase의 당시 범위·검사·Git 영수증은
수정하거나 후속 기능의 완료 증거로 확대하지 않는다.

## 진행 순환

1. Work가 총괄지시서와 현재 Phase 원문·선행 조건을 읽고 작업 지시를 작성한다.
2. Replit이 허용된 범위에서 구현하고 실제 acceptance 및 전체 등록 회귀를 실행한다.
3. 변경 범위·검사 결과·소스 지문·체크포인트·개발 브랜치 원격 SHA를 Work에 전달한다.
4. Work가 실제 증거를 확인한다. 실패는 범위 내 수정·전체 재검증 후 다시 검토한다.
5. 모두 PASS이고 선행 조건이 충족되면 다음 Phase를 지시한다. 매 Phase마다
   사용자에게 계속할지 묻지 않고 18까지 반복한다.

18단계는 릴리스 준비이지 운영 배포가 아니다. 운영 DB 조회·쓰기·migration,
실제 결제·환불·정산 활성화, main 반영·운영 배포는 이번 연속 진행 승인에 포함되지 않는다.
미확정 사업·법적·요금 정책을 임의 확정하거나 보존 기준·검사를 완화하지 않는다.

## 중단 조건

- 총괄지시서의 사용자 승인 Gate 또는 별도 정책 결정이 필요한 시점.
- 해결되지 않은 실패, 미구현 acceptance, 보존 위반, 누락된 Phase 원문,
  충족되지 않은 선행 조건 또는 실제 통신 경로 차단.
- 중단 시 BLOCKED/승인 대기를 명시하고 이유와 필요한 결정을 보고한다.
  실패를 PASS로 바꾸거나 다음 Phase를 이미 수행했다고 기록하지 않는다.

## 현재 확인된 사실

- 사용자 Phase 1·2·3 완료 기록은 보존한다. Phase 3의 최종 전체 검사는 17/17 PASS.
- 사용자 Phase 2는 데이터 확장이었으며 저장소 2단계 계정·로그인과 다르다.
  저장소 2~18단계는 현재 PENDING이다. 번호를 근거로 계정·로그인 등 미구현
  선행 기능을 완료로 간주하지 않는다.
- 저장소의 18단계 원문은 MASTER_SPEC.md, STAGE_PLAN.md, stages.json에 있다.
  Work가 별도 사용자 Phase 지시서를 사용한다면 그 원문과 대응관계를 확인해야 한다.
- **Work의 실행 위치·전달 경로는 아직 미확정이다.** 외부 Work와 통신하는
  자동 연결이나 상시 실행기가 이미 마련됐다고 주장하지 않는다.
  Replit 내부 총괄 역할로 순환할지, 별도 Work 서비스에 실제 연동할지 확인한다.

이 문서는 최신 진행 승인과 절차를 기록한다. 실제 통신/실행 프로그램을 설치한
것이나 Phase 4를 구현한 것, 과거 검사 이후 변경까지 검증한 것을 의미하지 않는다.
