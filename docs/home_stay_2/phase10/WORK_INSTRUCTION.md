권장 개발 정책: 활성/확인된 소비자 본인의 현재 견적 receipt와 명시적 신청 동의로
신청한다. 운영자에게30분 응답 기간을 주고, 승인 뒤2시간 결제 대기 기간을 준다.
즉시입주 정보는 자동 예약승인으로 해석하지 않는다. 공급자 승인은 항상 별도다.
응답/결제 기한은 DB 시각으로 판정하고 만료·거절·소비자 취소 때 슬롯을 해제한다.
소비자별 동시 활성 신청3개 한도로 재고 점유 남용을 제한한다.

같은 pool과 전체/호실의 descendant 공유재고를 DB 잠금·실제 겹침 검사로
직렬화한다. 공간 건물별 잠금을 일관된 순서로 잡고 checkout=다음 checkin은 허용한다.
scope graph cycle/미확인 pool은 허용하지 않는다. 다른 호실은 독립 예약을 허용한다.
운영자 blocked day·현재 승인/권한·정확한 날짜/최소 체류·소비자/운영자 본인 범위/
CSRF·revision·중복 요청을 재검증한다.

요금이 바뀐 미확정 신청은 오래된 가격으로 승인하지 않는다. 확정된 snapshot의
일/주/월 구성·총액·통화·가격/정책 버전은 이후 요금표 변경에도 그대로다.
결제확정은 서버의 신뢰할 수 있는 지급 증빙 adapter가 정확한 예약·금액·통화를
입증할 때만 가능하며 client의 paid/amount/role는 허용하지 않는다. 결제 증빙은
예약마다 유일하게 연결하고 replay·같은 확정 retry를 멱등 처리한다.

현재 actual PG·deposit·settlement Gate는 NOT_APPROVED다. owned fixture 지급 증빙은
실결제/운영승인이 아니다. 서버 증빙 adapter가 없으면 결제확정은 명시적으로 실패한다.
보증금·환불/세금 등 미확인 정책을 0원/무료/법정 확정으로 만들지 않는다.
예약신청/운영자 승인/결제대기와 결제확정 상태를 소비자·운영자 UI 모두에서 구분한다.
상세→신청과 상태조회·본인 취소, 운영자 목록→승인/거절이 API만 아닌 실제 UI로 작동한다.
