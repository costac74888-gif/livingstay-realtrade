# Phase15 내부 Work 검토

기존 admin_users 인증 구조를 확인했다. additive resolver는 기존
서명 세션에 의해 검증된 관리자 ID만 받으며 별도 비밀번호나 client ID
권한을 만들지 않는다. /admin을 삭제/대체하지 않았다.
기존 등록 검토 엔진의 submitted→approve/reject·권리·고지 확인을 재사용한다.

실제 원장의 등록·현재 요금/달력·예약·금융 조건·capture/refund/deposit/payout
이력을 읽는다. 전체 총계와 최근100개 표시를 구분하며 실제 지급은 실행하지
않는다. 가격은 기존 운영자 달력 엔진에서 관리한다.
draft/approve/archive에 차수 확인과 원자 감사 기록을 적용하고 감사 삭제를
막는다. FAQ59개 ID 범위·정책의 명시 비용/기간·초기 platform0%·프로모션
기간/대상·신고/리뷰 검토 대상·메모를 검증한다. 기록 편집은 재검토 초안이다.
승인 FAQ만 개발 도움말에 적용하고 승인 금융 정책은 새 조건에만 적용한다.
과거 계약/결제/취소 원장과 기존 약관/개인정보 문서는 보존한다.

프로모션 기록 승인은 실제 유료 노출·결제·매물 공개 승인을 대체하지 않으며,
리뷰 기록은 고객 리뷰 게시나 환불 실행이 아니다.
SQL 검사에서 권한/CSRF/재시도차수/감사롤백/불변원장/승인FAQ/비용미확인/
원장 조회/기존 검토 엔진을 확인했다. desktop/mobile에서 FAQ 편집·승인·보관·
재진입, 정책·프로모션·신고·리뷰 실제 폼의 생성·승인, XSS 비실행,
개인 권한 상실 때 비공개 DOM 제거와 nooverflow를 확인했다.
