근거: `home_stay_audit_2026_10/00_EXECUTIVE_SUMMARY.md`,

감사상의 정적 확인/추정/미확인 구분을 유지한다.

## 변경 불가 요구사항

- **PRESERVE-01** 기존 `master_buildings` 원장, ID, sequence, 분류와 모든 연결 관계를 보존.
  전 건축물 DB로 덮어쓰기·재구축·재번호·재분류 금지.
- **PRESERVE-02** 숙박시설 분류, 영업신고 원장(복수 허가·폐업 이력 포함),
  실거래, 공매/회차/현황조사, 지도, 관리자, 관심/채팅/알림 및 기존 기능 삭제 금지.
- **PRESERVE-03** 기존 수집·쿼터·승격 계보·Relay allowlist·인증·fail-closed 보존.
  기존 운영 Secrets/Relay 설정을 하네스가 수정하지 않는다.
- **PRESERVE-04** 기존 제한공개 매물 위치보호 유지: 정확한 주소·좌표·건물 ID·
  자동정보·응답 join을 통해 공개 위치를 역추적하지 못하게 한다.
- **PRESERVE-05** 기존 공매 네모형 마커 최대한 유지. 형태 변경이 필요하면 별도 검토.

## 소비자와 계정

- **PRODUCT-01** 소비자 단기임대 중심. 기존 숙박·부동산 데이터 플랫폼을 함께 유지.
- **AUTH-01** 이용자 진입은 카카오 로그인, 임대인/운영자/중개사는 이메일 로그인.
  provider와 role을 분리하고 동일 계정의 복수 역할·사업장 및 기존 이력 보존.
  이메일 일치만으로 소유권 미확인 계정을 자동 병합하지 않는다.
- **BUILDING-01** 모든 건물을 등록 후보로 허용. 원룸/오피스텔/아파트/빌라/연립/
  다세대/다가구/단독/도시형생활주택/숙박/농어촌/한옥/캠핑/상가/창고/기타 등.
  건축물대장 용도만으로 플랫폼 등록을 사전 차단하지 않는다.
  후보 허용은 법적 운영 허가·안전·전대 동의 면제 또는 예약 자동 승인을 의미하지 않는다.
- **BUILDING-02** 주소검색 → 건물 선택 → 대장 확인 → 좌표 확인 → 신규 매물 →
  매물별 지도 포인트. 등록 후보층과 기존 숙박 원장을 분리.

## 체류·가격·확정 예약

- **STAY-01** 실제 숙박시설로 분류되는 매물은 **1박부터**. 에어비앤비/도시민박,
  농어촌민박, 캠핑 등을 일괄 비숙박 7일로 처리하지 않는다.
  법적 영업분류/건축 용도/플랫폼 채널을 혼동하지 않으며 숙박 여부 결정 근거를 기록.
- **STAY-02** 숙박시설 외 단기임대는 **7일부터**. 6일 거절/7일 허용 경계를 검증.
- **PRICE-01** 숙박시설은 예약 **날짜별 요금**, 주말·연휴 등 날짜 override.
  체크인 포함/체크아웃 제외, 사업장 시간대와 연휴 정의를 명시적으로 고정하고
  날짜 누락·잘못된 범위는 조용한 0원/평일 요금 fallback 대신 명시적 처리.
- **PRICE-02** 비숙박시설은 **주·월 요금**, 적용 기간별 변경 가능.
  부분 주/월·월 길이·세금/관리비/보증금·취소 정책은 구현 전 별도 확정.
- **BOOKING-01** 확정예약에 선택일자·가격표 버전·일별/주별/월별 구성·통화·
  추가비용·할인·합계·정책 버전의 **가격 스냅샷** 저장.
  이후 가격표 변경이 확정예약 금액을 소급 변경하지 않는다.
  동시 확정/재시도 중복 예약·이중 청구 방지와 소유권 검증 필요.

## Super Map

- **MAP-01** 단기임대 기본 **ON**, 매매·영업권양도·공매는 **독립 레이어**.
  레이어별 상태/조회·합계·마커·좌측 패널 및 기존 숙박 데이터 통계 분리.
- **MAP-02** 레이어별 마커 형태 구분. 색만으로 구분하지 않는다.
  동일 좌표의 단기임대/매매/영업권/공매를 서로 가리지 않도록 offset/spiderfy/
  선택 목록 등 검증된 겹침 방지 방식. 표시 이동은 저장 좌표를 변경하지 않는다.
- **MAP-03** 클릭 종류에 따라 좌측 정보패널을 단기임대 정보/매물정보/
  영업권양도정보/공매정보로 전환. object ID와 layer를 함께 유지.
  비동기 응답·빠른 클릭·레이어 OFF·검색/뒤로가기에서 다른 상세로 덮어쓰지 않는다.
- **MAP-04** 기존 공매 네모 형태·선택 동작과 제한공개 위치보호 유지.
  모바일/데스크톱·동일좌표·키보드 조작을 acceptance에서 검증.

## 운영 안전과 승인

- **GATE-01** 운영 DB migration은 자동 진행 금지. schema diff/복구 계획/대상 지문/
  별도 소유자 승인 필요. 하네스에는 DB 연결·migration 실행 경로 없음.
- **GATE-02** 실제 PG·결제·정산은 자동 활성화 금지. test double만 사용.
  키/요금/환불/정산/법적 정책의 별도 승인 필요.
- **GATE-03** 운영 배포 자동 진행 금지. 별도 소유자 승인 및 수동 Publish 절차.
- **HARNESS-01** 모든 acceptance와 regression PASS, 검증된 파일 지문 일치,
  시작/완료 Git checkpoint가 있어야 다음 단계 시작 가능.
  SKIP/미구현/timeout/미검토 검사/오래된 PASS를 PASS로 취급하지 않는다.

## 브랜드 후보

**BRAND-01** 메인 브랜드 문구 후보: **‘머무는 곳을, 집처럼.’**

## 미확정 영역

취소·환불·세금·보험·신고/분쟁·정산주기, 월 요금의 일할 계산, 법적 운영 가능성,
숙박 분류의 최종 서비스 정책은 별도 결정 필요. 하네스 PASS는 사업 정책 승인이나
향후 18단계 기능 완성의 증거가 아니다.
