# Phase12 — 내부 Work 운영자 Dashboard 지시

선행: 사용자 Phase11 전체43그룹 PASS와 개발 원격·정확 SHA·main 미변경 확인.
원문16절의 방 등록/관리/예약/계약/매출·정산/채팅 업무를 기존 실제 기능으로
연결한다. 기존 매매·영업권·공매·실거래·가치/분석·DataLab·영업신고·파트너를
삭제하지 않고 기존 경로를 유지한다. Chat/My Booking 확장은 후속 Phase13이다.

본인 활성·승인 사업장 context만 조회하며 browser가 actor/scope를 지정하지 않는다.
SQL 원장 기반 전체 합계와 제한된 최근 목록을 구분한다. 빈 사업장은 실제0,
권한/자료 조회 실패는 빈0 대체가 아니라 오류다. 공개되지 않은 등록도 본인만
관리하고, 예약 승인·계약 동의·결제 증빙·실제 지급을 구분한다.

개발 금융 합계는 모의 증빙/실제 provider 증빙을 구분하고 실제 송금/수납 완료를
주장하지 않는다. 취소한 유료 예약의 역사적 증빙은 남기되 활성 숙박/보증금/
사업자 지급 검토 기준에서 제외한다. 늦은 지급도 정상 매출로 더하지 않는다.
검토 이벤트를 실제 환불/정산 완료로 합산하지 않는다. 초기 플랫폼 요율0%와
PG 비용 분리를 유지한다. 불명확한 점유율/수익률 분모는 추정하지 않는다.

Desktop/mobile의 실제 역할 검사·원장 조회·비어있지 않은 DOM·관리화면 이동을
검사하고 전체 registry/보존/내부 검토/개발 GitHub 저장 뒤 Phase13으로 이어간다.
운영 DB migration·실제 PG/정산·main 반영·배포 Gate는 NOT_APPROVED다.
