## 배치 진단과 수정의 범위
- Backfill Retry: 새 run_id만 생성하는 워크플로와 사전 등록된 running 소유자를 요구하는 CLI가 불일치했다.
  승인된 standalone용 --claim-run은 absent/non-running 상태만 원자적으로 확보하며, running 소유자를 교체하지 않는다.
  미등록 소유자는 명확한 메시지와 exit 75로 종료한다. 워크플로 정의만 갱신; 실행하지 않았다.
- Fill PK: 최근 실패 stage 원장 5행을 읽기 전용으로 조회하여 title 공급자의 HTTP 503 세 건을 확인했다.
  실제 공급자 장애 해소는 미확인이다. continuous 모드는 오류·retry_at을 보존하고 냉각·소유권 재확인 후 계속한다.
  비연속 실행의 전면 장애 중단 보호는 유지한다. 실제 운영 재수집은 하지 않았다.
- 기본 콘솔은 연락처를 마스킹하며, 명시적 비공개 보고 스트림만 원문 연락처를 받는다.
  실제 메일/SMS 수신자·본문·발송 반환값은 바꾸지 않았다.
