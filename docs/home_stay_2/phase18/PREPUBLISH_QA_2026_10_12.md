## 수정한 문제

1. 기본 개발 Project가 수동 GitHub 검사를 자동 실행하던 연결만 제거했다.
   독립 검사 정의·운영 수집·예약 스케줄은 유지했다.
2. 임시 검사 DB의 초기화에만 `initdb --no-sync`를 적용했다.
   운영 DB 설정이나 실행 중 DB의 트랜잭션 내구성은 변경하지 않았다.
3. 반복 Preview 검사는 재고에서 실제로 비어 있는 미래 날짜를 찾는다.
   재고 검사를 우회하거나 겹친 날짜를 강제 예약하지 않는다.
4. 예약 채팅 검사는 실제 문의 시작 버튼과 `items` 응답 계약을 따른다.
   예약만으로 문의가 자동 생성된다고 가정하지 않는다.
5. 이전 인증 조회 응답이나 이전 조회 실패가 최신 로그인·로그아웃·계정·사업자
   상태를 되돌리는 경합을 방어했다. 최신 조회의 실패는 계속 비인증으로 처리한다.
6. 멤버십 브라우저 검사는 초기 화면·인증 조회·로그인 응답 완료를 확인한다.
   실패한 assertion을 제거하거나 재시도로 숨기지 않았다.
7. 직접 프런트 빌드 CLI에서 프로젝트 패키지를 찾지 못하던 import 경로를 수정했다.
   실행기가 주입한 ROOT 없이도 CLI import가 되는 회귀 검사를 추가했다.

가격·기간 계산 및 원장 스키마의 동결 파일은 변경하지 않았다.

## 운영 게시를 막는 사항

| 항목 | 상태 | 아침에 필요한 확인 |
|---|---|---|
| 기존 실제 회원·사업자 신원 → 새 예약·채팅·원장 연결 | 미완료 | 기존 세션·역할·사업장·CSRF·인증 상태를 검증된 실제 repository/API에 연결 |
| 실제 토스 상점 테스트 승인·취소·환불 | NOT_RUN | 현재 두 테스트키는 문서 예제 형식이며 실제 상점 키 쌍으로 검증되지 않음 |
| 운영 DB 반영·전환 | NOT_APPROVED | 대상 DB 지문, 스키마 변경, 백업·복귀 한계, 변경창과 명시적 승인 |
| 운영 게시·공개 | 실행 안 함 | 위 실제 연결 증거와 승인된 전환·복귀 절차 확인 후 사용자가 게시 |

실제 토스 승인·실패·취소·환불·보증금 반환·지급·공급자 콜백 검증을
모의 결제 결과로 대체하지 않는다. 운영 DB 반영, main 병합, 게시, 실제 돈,
실제 이메일/SMS 발송은 실행하지 않았다. 물리 iPhone 검증도 아니다.

운영 로그에서 관측된 기존 외부 API 지연·DB 연결 종료·워커 재기동은
이 격리 검사로 해결되었다고 주장하지 않는다. 현재 운영 환경의 건강 상태도
별도 운영 진단 없이 통과로 표시하지 않는다.

마지막 모바일 캡처에서 페이지와 가상 목록은 표시됐지만 캡처 도구의
HTTP localhost에서 지도 CDN의 HTTP 스크립트가 HTTPS 전용 CSP에 차단됐다.
이 이미지로 실제 HTTPS 도메인의 지도 SDK 검증을 대신하지 않는다.
