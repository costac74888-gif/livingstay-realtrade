# 단계별 진행 상태 — 완료·운영 승인 아님

## 요청 범위와 안전 경계

요청 순서는 기존 API/전체 회귀 복구, 격리 개발 Preview 통합,
Toss 테스트 SDK/API 검증이다. 이 문서는 중간 작업 기록이며 어느 단계도
자동 승인하거나 Phase 18 완료를 선언하지 않는다.

운영 DB·실제 외부 발송·실결제·실환불·정산·main 병합·운영 게시를
허용하지 않는다. 테스트 접속은 직접 생성한 임시 PostgreSQL UNIX
socket과 정해진 owned 웹 origin으로 제한한다.

## 확인된 결과

- 기존 API의 최초 7개 실패를 격리 DB에서 재현했다.
- 실제 표본 대신 공개 표본명과 가상 주소·신고자료를 사용한다.
  원본 API assertion은 변경하지 않았다.
- 관리자 공매 참고행에 빠져 있던 공통 원본 컬럼을 보완했다.
  참고행을 숙박 합계에 더하지 않는다.
- 수정 후 API 검사는 PASS로 전환됐다. 기존 smoke도 재실행했다.
- 매물 삭제·철회, 운영자 사진 관리, 관리자 방문 추이,
  등록 화면의 선택 재검증은 PASS다.
- 사진 순서 변경 UI를 기존 PUT API에 연결했다. 실패 시 로컬 순서를
  원복하며 대표 설정·삭제 기능을 유지한다.
- 최근검색은 10개 보관, 5개 화면 표시를 분리했다. 두 기존 요구를
  하나의 상수로 충족할 수 없으므로 화면 검사도 표시 상수를 읽는다.
- 기존 화면 검사에서 expect의 세 번째 인수로 잘못 전달되어 무시되던
  신고객실수 조건을 AND 조건으로 포함했다. 검사 강도를 낮추지 않았다.
- 개인정보 검사 결과는 vulnerabilities 빈 배열이다.
  이는 모든 종류의 보안 취약점이 없다는 선언이 아니다.

## 아직 통과하지 않은 전체 회귀

- 단일 pytest 실행에서 1,238 PASS, 52 FAIL, 147 ERROR, 2 SKIP를
  확인했다. 기존 SKIP를 PASS로 바꾸거나 새 SKIP를 넣지 않았다.
- 모듈별 별도 인터프리터로 전체 150개 pytest 모듈을 실행했으나
  24개 모듈은 아직 실패했다. 이 결과를 전체 통과라고 표시하지 않는다.
- 기존 범용 목록 중 마지막 보존 결과는 26개 실행,
  19개 PASS, 7개 FAIL이다. 나머지 목록을 실행하지 않은 상태를
  최초 115개 전체 회귀 PASS로 해석하지 않는다.
- 해당 실행은 일부 브라우저의 기본 주소가 기존 5000번 앱을 가리키는
  것을 발견해 중단했다. 이후 owned BASE_URL 설정과 페이지·Node HTTP·
  fetch·Request 객체·Playwright API context 차단을 보강했다.
  전송 경계 부정 검사는 PASS지만 전체 브라우저 재검증은 아직 필요하다.
- 안전한 비교용 DB명을 분리했고 반복 클래스 초기화 시 owned HS2
  fixture를 초기화하도록 고쳤다. 이 수정으로 나머지 회귀까지
  모두 해결됐다고 선언하지 않는다.

## 증거 위치

실행 로그는 생성물 디렉터리에 있으며 Git에 올리지 않는다.

- `.local/suite-audit/owned-current/`: 범용 체크별 결과·pytest 로그.
- `.local/hs2-harness/step1-registered-final.json`: 등록된 검사 실행 기록.
  source_unchanged가 false인 실행은 최종 소스 지문 통과가 아니다.
- `/tmp/hs2-step1-api-baseline.log`: 최초 API 실패 재현.

기존 Harness baseline을 다시 생성하지 않았으며 frozen 13개,
기존 route 616개 및 필수 항목 10개 보존 검사를 유지한다.

## 다음 두 단계

새 화면의 접근 가능한 통합 개발 Preview 및 PC/모바일 전체 가입·
로그인·역할·등록·검색·예약 여정 검증은 미완료다. 기존 개별 fixture
화면 검사를 이 통합 Preview 검증으로 대체하지 않는다.

Toss 테스트 SDK/API의 실제 승인·실패·취소·웹훅·환불을 실행하지 않았다.
OwnedSandbox 검사는 Toss 공급자 검증이 아니다. 현재 제공되는 결제
연동 선택 경로에는 Toss가 없으며 임의로 Stripe/Whop으로 바꾸지 않았다.
금융 원장·재고 관련 기존 가상 검사를 실제 Toss 검증이라고 표시하지 않는다.
