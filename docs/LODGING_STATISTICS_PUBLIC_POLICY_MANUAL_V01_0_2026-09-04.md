## 1. 목적과 적용 범위

이 문서는 숙박 통계의 용어, 유형별 집계 단위, 신고율 산식, 캠핑 시설·사이트
집계, 영업상태 처리와 채널별 공개 범위를 하나의 계약으로 정한다. 관리자 화면과
공개 화면은 같은 승인 원본과 집계 규칙을 사용하되, 응답 필드는 역할에 맞게
분리한다.

이 문서가 다루는 범위는 다음과 같다.

1. 생활·관광·일반·에어비앤비·농어촌민박·캠핑·한옥·복합의 집계 단위
2. 건물수·시설수·호실수·신고업체수·신고객실수·사이트수와 신고율
3. 캠핑 건물형·대지형 시설의 중복 제거와 사이트 4분류
4. 활성·휴업·폐업·제외·검토 상태의 보존 및 공개 원칙
5. 공개 API·공개 화면·관리자 화면의 필드 범위와 개인정보 보호
6. 수치 예시와 산식 검증표

다음은 이 문서의 범위가 아니다.

- 외부 API·CSV 수집 장애의 상세 복구 절차
- 화면 디자인 또는 UI 코드 변경
- 운영 DB의 데이터 수정

## 2. 권위와 공통 원칙

### 2.1 충돌 처리

1. 법령, 정보주체 동의 또는 별도 계약 중 더 엄격한 기준을 먼저 적용한다.
2. 공개·개인정보는 POL-EXPOSURE-001을 우선한다.
3. 수집·검증·승격·보존은 POL-DATA-003을 우선한다.
4. 통계 산식은 이 문서와 현재 승인된 서버 집계 계약을 함께 적용한다.
5. 화면 문구·툴팁이 서버 산식과 다르면 화면 문구를 근거로 산식을 바꾸지 않는다.
6. 코드와 본 문서가 다르면 공개 확대와 운영 반영을 멈추고 둘을 먼저 일치시킨다.

### 2.2 공통 집계 원칙

1. 공개 통계의 신고 분자에는 `영업/정상`으로 분류된 활성 신고만 넣는다.
2. 휴업·폐업·취소·말소·만료·정지·제외·검토 상태는 활성 분자에서 제외한다.
3. 관리번호가 같은 행은 같은 집계 안에서 한 번만 센다.
4. 관광 원본과 기존 숙박 원장의 동일 신고는 주소, 허가일과 객실수 등 신뢰 가능한
   식별값이 일치할 때 기존 신고를 우선해 한 번만 센다.
5. 주소 매칭은 정규화 도로명을 우선하고, 도로명 결과가 없을 때 지번을 보조로 쓴다.
6. 같은 신고가 여러 건물에 매칭되면 대표 건물 한 곳에만 귀속한다.
7. 생활숙박의 신고객실수는 건물별 건축물대장 호실수를 넘지 않도록 상한을 둔다.
8. 분모가 0이면 신고율은 0%가 아니라 `해당 없음(null, 화면에서는 -)`으로 표시한다.
9. 비율은 `(분자 ÷ 분모) × 100`을 계산한 뒤 소수점 첫째 자리로 반올림한다.
10. 전국 “전체” 신고율은 유형별 서로 다른 단위를 억지로 객실 단위로 환산하지
    않고, 각 유형의 승인된 분자·분모를 합한 가중 지표로만 제공한다.

### 2.3 기준일 현재 구현 불일치

2026-09-04 코드 대조와 API 검증에서 다음 불일치가 확인되었다. 이는 현행 허용
기준이나 선례가 아니며, 관련 코드 교정과 회귀검사를 마치기 전 공개 확대를 하지
않는다.

1. 관리자 일반숙박 신고율 일부 경로가 활성 신고업체수÷일반숙박 건물수와 다른
   건물 상태 산식을 사용한다.
2. 공개 전국숙박업통계 응답에 내부 신고율 분자·분모 또는 내부 캠핑 분류값이
   포함될 수 있다.
3. 공개 데이터랩 일부 경로에 폐업 상태별 통계가 남아 있다.

교정 작업은 본 문서의 F-03, 5.3, 6장과 7장의 공개 허용 목록을 기준으로 한다.

관광·에어비앤비·농어촌민박·캠핑·한옥·복합의 신고율은 **객실 비율이 아니라
건물 커버리지**다. 해당 유형의 신고객실수와 건축물대장 호실수는 모집단 의미가
다르므로 서로 나누지 않는다.

### 4.2 생활숙박 신고율

```text
생활 신고율 =
  건물별 호실수로 상한 처리한 정상영업 신고객실수 합계
  ÷ 생활숙박 건축물대장 호실수 합계
  × 100
```

- 한 신고가 여러 건물에 중복 귀속되지 않게 한다.
- 한 건물의 신고객실 합계가 그 건물 호실수보다 크면 호실수까지만 분자에 넣는다.
- 전국 생활숙박, 시도별 생활숙박과 건물 상세는 같은 주소 우선순위와 상한 규칙을
  사용한다.

### 4.3 일반숙박 신고율

```text
일반숙박 신고율 =
  정상영업 일반숙박 고유 신고업체수
  ÷ 일반숙박 건물마스터 고유 건물수
  × 100
```

일반숙박은 건축물대장 호실수와 신고객실수의 모집단이 직접 비교되지 않으므로
객실 비율을 쓰지 않는다. 같은 신고가 여러 원본에 있으면 중복 제거하지만, 한
건물에 실제로 서로 다른 활성 신고가 둘 이상 있으면 각각 신고업체로 센다.

일반숙박 세분류(여관업, 여인숙업, 일반호텔 등)는 세분류별 건물수,
활성 신고업체수와 신고객실수를 별도로 계산한다.

### 4.4 관광·에어비앤비·농어촌민박·캠핑·한옥·복합 신고율

```text
유형별 신고율 =
  해당 유형의 정상영업 신고가 하나 이상 연결된 고유 건물수
  ÷ 해당 유형의 건물마스터 고유 건물수
  × 100
```

같은 건물에 정상과 비활성 신고가 함께 있으면 정상 신고가 있는 건물로 센다.
비활성 신고만 있으면 분자에 넣지 않는다.

### 4.5 전체 가중 신고율

```text
전체 분자 =
  생활 상한 처리 신고객실수
  + 일반 활성 고유 신고업체수
  + 나머지 확정 유형의 활성 신고 연결 건물수 합계

전체 분모 =
  생활 건축물대장 호실수
  + 일반숙박 건물수
  + 나머지 확정 유형의 건물수 합계

전체 신고율 = 전체 분자 ÷ 전체 분모 × 100
```

전체 신고율은 서로 다른 유형 단위를 합한 운영용 가중 지표다. 이를 “전체
신고객실 비율”이나 유형 간 객실 생산성 비교로 해석하지 않는다.

## 5. 캠핑 시설수와 사이트수

### 5.1 캠핑 고유 시설수

캠핑 시설수는 다음 식으로 계산한다.

```text
캠핑 시설수 =
  정상영업 건물 연결 시설
  + 정상영업 미연결 대지형 시설
  - 신뢰 가능한 동일 시설 중복
```

세부 규칙은 다음과 같다.

1. 입력 원장은 일반야영장업·자동차야영장업 중 `영업/정상`만 사용한다.
2. 건물에 연결된 행은 건물 ID별로 한 시설만 센다.
3. 건물에 연결되지 않은 대지형·사업장 행은 정규화 주소와 정규화 상호가 모두
   같은 경우에만 동일 시설로 통합한다.
4. 연결 시설과 같은 주소·상호 키를 가진 미연결 행은 중복으로 제외한다.
5. 주소 또는 상호가 없어 신뢰 키를 만들 수 없으면 관리번호별 별도 시설로
   보존해 과도한 병합을 하지 않는다.
6. 중복 원본 중 대표행은 사이트 4종 합계가 가장 완전한 행을 우선한다.
7. 고캠핑 API 시설 총수는 공개 시설수의 단독 기준으로 사용하지 않는다.

### 5.2 사이트 4분류

| 번호 | 공개 분류 | 집계 내용 |
|---:|---|---|
| C-01 | 일반야영 | 일반야영 사이트 수 |
| C-02 | 자동차야영 | 자동차야영 사이트 수 |
| C-03 | 글램핑 | 글램핑 사이트 수 |
| C-04 | 카라반 | 설치 카라반 수 + 개인 카라반 사이트 수 |

```text
캠핑 사이트수 =
  일반야영 + 자동차야영 + 글램핑 + 카라반
```

음수, 숫자가 아닌 값과 비어 있는 값은 합계에서 0으로 처리하되 원본 검토 상태는
별도로 보존한다. 사이트수는 대표 고유시설 행에서만 합산해 원본 간 중복 합계를
막는다.

### 5.3 단일·복합·미확인 표시

| 내부 분류 | 판정 | 공개 표시 |
|---|---|---|
| `general_only` | 일반야영만 양수 | 일반야영 |
| `auto_only` | 자동차야영만 양수 | 자동차야영 |
| `glamping_only` | 글램핑만 양수 | 글램핑 |
| `caravan_only` | 카라반만 양수 | 카라반 |
| `confirmed_mixed` | 둘 이상의 사이트 유형이 양수 | 복합 |
| `unknown` | 세부 사이트 수가 없거나 유형 확정 불가 | 복합 |

공개 화면은 `confirmed_mixed + unknown`을 복합 시설수로 합쳐 표시한다. 내부
데이터와 관리자 검증에서는 실제 복합과 미확인을 계속 분리해, 미입력값을 실제
복합시설로 오인하지 않게 한다.

## 6. 영업상태별 보존·집계·공개

| 번호 | 내부 상태 | 대표 원문 | 원장 보존 | 활성 통계 분자 | 공개 개별정보 | 관리자 검증 |
|---:|---|---|---|---|---|---|
| S-01 | active | 영업/정상 | 보존 | 포함 | 승인된 최소 시설정보만 가능 | 가능 |
| S-02 | temporarily_closed | 휴업 | 보존 | 제외 | 상태·날짜·건수 모두 금지 | 업무상 필요 범위 |
| S-03 | closed | 폐업·취소·말소·만료·정지·중지 | 보존 | 제외 | 상태·날짜·건수 모두 금지 | 업무상 필요 범위 |
| S-04 | excluded | 제외·삭제·전출 | 보존 또는 감사정책에 따른 격리 | 제외 | 금지 | 검증 목적 |
| S-05 | review | 미확인 상태값 | 원문과 함께 보존 | 제외 | 금지 | 검토 필요 |

적용 원칙:

1. 비활성 이력은 삭제하지 않는다. 원본 계보, 정정, 중복 판정과 감사에 필요하다.
2. 공개 목록·지도·상세·검색·공유 미리보기에는 비활성 상태, 날짜, 아이콘, 색상,
   문구와 개별 건수를 넣지 않는다.
3. 같은 건물에 정상과 비활성 신고가 함께 있으면 공개 대표와 활성 집계는 정상을
   우선한다.
4. 비활성 신고만 있는 건물은 내부 원장과 허용된 관리자 화면에 보존할 수 있으나
   그 신고를 근거로 개별 시설을 공개하지 않는다.
5. 비활성 상태별 건수, 폐업률, 지역별 순위와 내부 중간값은 공개하지 않는다.
6. 작은 집단이나 교차 필터로 개별 영업상태를 추론할 수 있으면 집계를 합치거나
   제공하지 않는다.

## 7. 채널별 공개 범위

### 7.1 공개 통계 API

공개 전국 숙박 통계 응답은 다음 최소 필드만 허용한다.

| 공통 필드 | 의미 |
|---|---|
| `type` | 공개 숙박 유형 |
| `building_count` | 유형별 건물수. 캠핑 화면은 별도 시설수를 우선 사용 |
| `units` | 건축물대장 호실수 |
| `biz_count` | 중복 제거한 활성 신고업체수 |
| `room_count` | 활성 신고객실수 |
| `report_rate` | 유형별 최종 신고율 |

캠핑 행과 전체 행에는 다음 집계 필드를 추가할 수 있다.

- `camping_facility_count`
- `camping_site_count`
- `camping_general_site_count`
- `camping_auto_site_count`
- `camping_glamping_site_count`
- `camping_caravan_site_count`
- 공개 라벨로 합친 캠핑 시설 유형별 시설수

캠핑 시설 유형별 시설수는 `일반야영`, `자동차야영`, `글램핑`, `카라반`,
`복합`의 공개 라벨만 제공한다. 내부 `confirmed_mixed`와 `unknown`은 공개
응답에서 각각 노출하지 않고 둘을 합한 `복합`만 제공한다.

일반숙박에는 공개 승인된 세분류 `sub_rows`를 제공할 수 있다. 공개 응답에는
개별 관리번호, 상호, 주소, 연락처, 원본 행, 영업상태·상태일, 내부 ID, 중복 판정키,
원본별 출처 행, 검토 메모, 오류, 캐시 상태 키와 내부 분자·분모를 넣지 않는다.

### 7.2 공개 화면

1. 공개 화면은 공개 API의 최소 projection만 렌더링한다.
2. 캠핑은 건물수 대신 고유 시설수, 호실수 대신 사이트수를 우선 표시한다.
3. 캠핑 세부표는 일반야영·자동차야영·글램핑·카라반·복합을 표시한다.
4. 캠핑 미확인은 복합에 합쳐 보이되, 이를 “확인된 복합”이라고 설명하지 않는다.
5. 신고율 툴팁은 유형별 산식과 같아야 하며 객실 기준과 건물 기준을 혼용하지 않는다.
6. `null` 비율은 `-`로 표시하고 0%로 바꾸지 않는다.
7. 휴·폐업 상태별 통계, 개별 비활성 시설과 연락처는 HTML, 숨김 DOM,
   초기 상태 객체, 메타태그 또는 클라이언트 로그에도 넣지 않는다.

### 7.3 관리자 화면과 관리자 API

관리자는 인증과 업무 목적을 확인한 뒤 다음 정보를 추가로 볼 수 있다.

- 개별 원장의 관리번호, 원문 업태, 원문 영업상태와 상태 상세
- 원본별 행, 주소 매칭 결과, 중복·대표행 판단 자료
- 비활성·검토 상태와 갱신 시각
- 내부 산식 검증용 분자·분모, 캐시·수집 상태와 오류 요약

관리자 권한도 비밀번호·인증번호·세션·재설정 토큰·API 키·DB 접속값의 열람 근거가
되지 않는다. 전화번호 등 개인정보는 실제 운영 목적에 필요한 최소 범위에서만
제공하며 통계 내보내기에는 기본 포함하지 않는다.

관리자 통계 객체를 필터 없이 공개 route에 재사용하지 않는다. 같은 집계 원본을
쓰더라도 공개 serializer/projection을 별도로 거쳐 금지 필드를 제거한다.

### 7.4 개인정보·보안 금지 항목

다음 값은 공개 API·화면·다운로드·메타태그·로그에 넣지 않는다.

- 전화번호, 이메일, 원본 IP와 접속이력
- 비밀번호 원문·해시, 인증번호, 세션·OAuth·재설정 토큰
- 외부 API 키, DB URL, 서명 URL과 저장소 내부 객체 키
- 관리자 내부 ID, run ID, 상태 키, 검토 메모, 원본 오류 전문
- 개별 휴업·폐업·취소·말소 상태 및 날짜
- 내부 신고율 분자·분모와 비활성 상태별 중간 집계

화면에서 숨기는 것으로 보호를 대신하지 않는다. 서버 조회와 직렬화 단계에서
제거하고, 역할별 응답을 공유 캐시하지 않는다.

## 8. 예시 수치와 산식 검증표

아래 값은 산식 설명용 가상 수치이며 운영 현황이 아니다.

### 8.1 생활숙박 예시

| 건물 | 건축물대장 호실수 | 정상 신고객실 합계 | 상한 적용 분자 |
|---|---:|---:|---:|
| A | 80 | 75 | 75 |
| B | 40 | 50 | 40 |
| C | 30 | 0 | 0 |
| 합계 | 150 | 125 | 115 |

```text
생활 신고율 = 115 ÷ 150 × 100 = 76.7%
```

B의 신고객실 50실은 건축물대장 40호실을 넘으므로 40실까지만 분자에 넣는다.

### 8.2 일반숙박 예시

| 구분 | 수량 |
|---|---:|
| 일반숙박 건물 | 20 |
| 활성 고유 신고업체 | 19 |

```text
일반숙박 신고율 = 19 ÷ 20 × 100 = 95.0%
```

한 건물에 서로 다른 활성 신고가 여러 개 있으면 각각 신고업체로 센다. 따라서
일반숙박 신고율은 100%를 넘을 수 있으며, 이는 객실 비율이나 건물 점유율이 아니다.

### 8.3 건물 커버리지 유형 예시

| 유형 | 유형 건물수 | 활성 신고 연결 건물수 | 신고율 |
|---|---:|---:|---:|
| 관광 | 50 | 42 | 84.0% |
| 농어촌민박 | 30 | 24 | 80.0% |
| 한옥 | 12 | 9 | 75.0% |
| 복합 | 8 | 6 | 75.0% |

관광 신고객실이 3,000실이어도 관광 건축물대장 호실수로 나누지 않는다.

### 8.4 캠핑 예시

활성 원장에 건물 연결 6행, 미연결 대지형 5행이 있고, 연결 행 내부에서 같은
건물 중복 1건, 미연결 주소+상호 중복 1건, 연결 시설과 같은 미연결 중복 1건이
확인되었다고 가정한다.

```text
건물 연결 고유시설 = 6 - 1 = 5
미연결 대지형 고유시설 = 5 - 1 - 1 = 3
캠핑 시설수 = 5 + 3 = 8
```

대표 고유시설 8개의 사이트가 일반 40, 자동차 25, 글램핑 10, 설치 카라반 6,
개인 카라반 사이트 4라면 다음과 같다.

```text
카라반 = 6 + 4 = 10
캠핑 사이트수 = 40 + 25 + 10 + 10 = 85
```

단일 일반야영 2곳, 단일 자동차야영 1곳, 단일 글램핑 1곳, 단일 카라반 1곳,
확인 복합 2곳, 미확인 1곳이면 공개 복합 시설수는 `2 + 1 = 3곳`이다. 내부에서는
확인 복합 2곳과 미확인 1곳을 분리 보존한다.

### 8.5 전체 가중 신고율 예시

| 유형군 | 분자 | 분모 |
|---|---:|---:|
| 생활 신고객실/호실 | 115 | 150 |
| 일반 활성 신고업체/일반 건물 | 19 | 20 |
| 기타 유형 활성 신고 건물/유형 건물 | 81 | 100 |
| 합계 | 215 | 270 |

```text
전체 가중 신고율 = 215 ÷ 270 × 100 = 79.6%
```

이 79.6%는 객실만의 비율이 아니라 유형별 승인 단위를 합한 가중 지표다.

### 8.6 산식 검증표

| 번호 | 검증 항목 | 입력 또는 조건 | 기대 결과 |
|---:|---|---|---|
| V-01 | 활성 상태 | 영업/정상 | 활성 분자 포함 |
| V-02 | 비활성 상태 | 휴업·폐업·취소·말소 | 활성 분자·공개 개별정보 제외 |
| V-03 | 원본 간 중복 | 동일 주소·허가일·객실수의 관광/기존 원장 | 기존 신고 우선, 한 번 집계 |
| V-04 | 도로명 우선 | 도로명과 지번 양쪽에 서로 다른 신고 | 도로명 결과 사용 |
| V-05 | 생활 상한 | 호실 40, 신고객실 50 | 분자 40 |
| V-06 | 생활 무분모 | 호실수 0 | 신고율 null |
| V-07 | 일반 복수 신고 | 한 건물에 서로 다른 활성 신고 3건 | 분자 신고업체수 3 |
| V-08 | 정상+폐업 | 같은 건물에 정상 1, 폐업 1 | 활성 신고 건물 1 |
| V-09 | 폐업-only | 같은 건물에 폐업만 존재 | 활성 분자 0, 개별 공개 금지 |
| V-10 | 캠핑 건물 중복 | 같은 건물 ID의 활성 원장 2행 | 시설 1 |
| V-11 | 캠핑 대지 중복 | 같은 정규 주소+상호의 미연결 2행 | 시설 1 |
| V-12 | 불확실한 대지 | 주소 또는 상호가 없어 신뢰 키 없음 | 관리번호별 별도 보존 |
| V-13 | 카라반 결합 | 설치 6, 개인 사이트 4 | 카라반 10 |
| V-14 | 캠핑 복합 | 두 사이트 유형이 양수 | 내부 confirmed_mixed, 공개 복합 |
| V-15 | 캠핑 미확인 | 사이트 수 없음 | 내부 unknown, 공개 복합 |
| V-16 | 공개 projection | 관리자 원본 객체를 공개 직렬화 | 허용 필드만 남고 상태·개인정보 제거 |

## 9. 변경·배포 전 확인 절차

통계 또는 공개 필드를 변경할 때 다음 순서로 확인한다.

1. 변경 유형의 집계 단위와 분자·분모를 F-01~F-08 중 하나에 연결한다.
2. 활성 상태 필터가 주소 매칭과 중복 제거 뒤에도 일관되게 적용되는지 확인한다.
3. 생활숙박은 건물별 객실 상한, 일반숙박은 건물 기준 분자·분모를 확인한다.
4. 캠핑은 시설수와 건물수, 사이트수와 객실수를 혼용하지 않는지 확인한다.
5. 카라반 결합 및 confirmed_mixed/unknown 내부 분리를 확인한다.
6. 공개 serializer가 허용 목록 방식인지, 관리자 필드가 섞이지 않는지 확인한다.
7. 공개 API, HTML, DOM, 메타태그와 다운로드에서 비활성 상태·개인정보를 검사한다.
8. V-01~V-16에 해당하는 자동 또는 표본 검증 증거를 남긴다.
9. 캐시를 갱신한 뒤 공개 화면과 관리자 화면이 같은 승인 집계 시점을 쓰는지 확인한다.
10. 산식·필드·정책 중 하나라도 일치하지 않으면 배포와 공개 확대를 중단한다.
