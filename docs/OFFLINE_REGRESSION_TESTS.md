# 운영 DB 없는 기존 회귀 검사

## 실행

```sh
python tests/run_offline_suite.py --results .local/suite-audit/offline
python tests/run_offline_suite.py --only "Python pytest" --only api_test.py
python tests/smoke_test.py
python tests/api_test.py
python tests/test_owned_offline_runtime.py
```

`--only`는 정확한 검사 이름으로 선택한다. 선택하지 않으면 Python 수집,
독립 스크립트, JS/브라우저 검사, 등록된 격리 DB·브라우저 검사를 모두 실행한다.
검사 실패는 원래 종료 코드로 남으며 전체 명령도 0이 아닌 코드로 끝난다.

## 격리 경계

- 상위 환경의 운영 DB URL, 서비스 인증값, 실제 연락처·배포 호스트를
  전달하지 않는다. Python 설치 경로 등 실행에 필요한 값만 허용한다.
- 임시 PostgreSQL은 TCP를 열지 않는다. 드라이버의 공개·내부·네이티브
  연결 경계에서 소유한 UNIX 소켓, 포트, 사용자, DB만 허용한다.
- 기준 DB가 필요한 지문 검사는 같은 임시 클러스터의 다른 **읽기 전용**
  DB를 사용한다. 운영 DB를 읽는 검사로 해석하면 안 된다.
- 40개 가상 건물, 가상 신고·중개·거래·공매 원장을 생성한다. 과거 검사가
  이름으로 찾는 표본은 호환 라벨만 사용하고 주소·연락처·원장은 가상이다.
  운영 데이터는 복사하지 않는다.
- 이메일·SMS는 공통 발송 함수의 비활성화 모드를 사용한다. Python 소켓과
  외부 DNS도 차단하여 모의 처리 누락이 실제 발송으로 이어지지 않게 한다.
- 브라우저는 소유한 앱 서버 또는 검사 프로세스가 만든 서버만 사용할 수
  있다. Kakao SDK는 가상 구현, Chart.js는 설치된 로컬 파일을 사용한다.
  가상 사진도 같은 서버가 제공하며 수기입금 화면에는 가상 계좌만 설정한다.
- Playwright 경로 가드뿐 아니라 필수 로컬 프록시에서 외부 HTTP/CONNECT를
  차단한다. 개별 페이지의 `route.continue`, 리디렉션, APIRequestContext도
  이 경계를 벗어나지 못한다. Node 소켓도 같은 소유 포트만 허용한다.
- Git 실행은 원본 비교용 `show`·`diff`만 허용한다. 수집·결제·배포 명령이나
  단계 승인 명령을 실행하지 않는다. HS2 검사는 체크 함수만 호출하며
  운영 승인 상태를 변경하지 않는다.

## 독립 실행과 결과

격리 DB 모듈, 가드 계약 모듈, 격리 브라우저 모듈은 기존의 전용 실행기를
사용한다. 이 모듈들은 통합 pytest에서 중복 수집하지 않고 반드시 별도
체크로 실행한다. 건축정보 파서 단위 검사도 별도 프로세스에서 실행한다.
통합 앱 검사 뒤에 남은 백그라운드 보강 작업이 파서 검사의 모의 응답
큐를 소비할 수 있기 때문이다. 해당 12개 단위 검사의 assertion은 그대로다.
격리 경계 검사 모듈 역시 자신의 DB 소유권을 생성하므로, 다른 DB 소유권이
이미 로드된 통합 앱 검사 프로세스 안에 중첩하지 않고 독립 실행한다.

각 검사 로그, fixture 로그, 전체 `summary.json`을 결과 디렉터리에 남긴다.
pytest는 JUnit XML과 실패·미실행 사례도 기록한다. 기존 업로드 자료가 없어
원래 검사에서 skip한 항목은 `PASS_WITH_SKIPS`로 구분하고 원래 사유를 보존한다.
**skip은 해당 사례가 검증되었다는 뜻이 아니다.**

`failure_kind`는 초기 분류이지 자동으로 코드 결함을 확정하는 판정은 아니다.

| 분류 | 의미 |
|---|---|
| `fixture_setup` | 임시 DB·서버 준비 실패. 로그를 확인하고 준비를 고친다. |
| `isolation_boundary` | 금지한 연결·프로세스 경로에 도달했다. 가드를 해제하지 않는다. |
| `timeout` | 제한 시간 내 종료하지 못했다. 자식 프로세스 그룹을 정리한다. |
| `assertion_or_fixture_contract` | 실제 assertion 실패. 표본·역할·SDK 설정 오류인지, 제품 코드 또는 오래된 검사 계약인지 별도 확인한다. |

격리 경계 자체는 별도 검사로 실제 PostgreSQL·브라우저·외부 접근 탐지용
로컬 서버를 사용해 검증한다. 탐지 서버에는 브라우저·Node·리디렉션·준비
요청이 한 건도 도착하지 않아야 한다.

검사가 인증 화면 뒤 UI를 확인할 때는 해당 검사의 가상 계정 fixture를
사용한다. 운영 로그인이나 앱의 인증 우회는 하지 않는다.
