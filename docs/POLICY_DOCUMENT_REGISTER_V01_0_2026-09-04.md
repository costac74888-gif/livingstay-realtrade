## 1. 문서 상태 정의

| 상태 | 의미 |
|---|---|
| 현행 | 현재 작업과 운영 판단의 기준 |
| 보조 | 현행 정책을 보완하는 기술·운영 가이드 |

| 대체됨 | 더 최신 문서가 권위를 승계함 |

충돌 시 우선순위:

1. 가장 최근 기준일의 현행 정책
2. 영역별 현행 매뉴얼
3. 코드와 설정에서 확인한 실제 실행 계약
4. 역사 보고서

문서와 코드가 다르면 운영 변경을 중단하고 문서 또는 코드를 먼저 일치시킨다.

## 4. 권장 폴더 구조

```text
docs/
  README.md
  policies/        # 장기간 유지하는 규칙
  runbooks/        # 운영자가 순서대로 실행하는 절차
  manuals/         # 기능·원본별 사용 설명
  reports/         # 특정 시점 검증 결과, 수정하지 않는 역사자료
    2026/
    archive/
  templates/       # 감사·장애·배포 보고서 양식
  registers/       # 문서대장과 CSV 목록
exports/           # 다운로드용 PDF·DOCX·HTML
```

현재 문서는 기존 링크 보존을 위해 `docs/` 바로 아래에 둔다. 다음 대규모 문서 정리 시 참조 검색과 redirect 안내를 먼저 준비한 뒤 위 구조로 이동한다.

## 5. 파일명 규칙

### 5.1 현행 정책·매뉴얼

```text
<영문문서명>_V<주버전>_<부버전>_<YYYY-MM-DD>.md
```

예:

```text
PHOTO_RETRIEVAL_OPERATIONS_MANUAL_V01_0_2026-09-04.md
```

### 5.2 검증 보고서

```text
<YYYY-MM-DD>_<영역>_<보고서명>.md
```

보고서는 당시 증거이므로 기존 파일을 덮어쓰지 않는다. 정정은 새 날짜 또는 correction 번호로 작성한다.

### 5.3 다운로드 파일

```text
HOME_AND_STAY_<문서명>_V<버전>_<YYYY-MM-DD>.pdf
HOME_AND_STAY_<문서명>_V<버전>_<YYYY-MM-DD>.docx
HOME_AND_STAY_<문서명>_V<버전>_<YYYY-MM-DD>.html
```

## 6. 버전 규칙

| 변경 | 버전 |
|---|---|
| 정책 의미·책임·승인 단계 변경 | 주버전 증가 |
| 새 원본·버튼·절차·검증 항목 추가 | 부버전 증가 |
| 오탈자·링크·표현 명확화 | 패치 증가 |

예:

- V.03.0 → V.04.0: 개발→운영 승인 구조 자체 변경
- V.03.0 → V.03.1: 새 원본과 검증 단계 추가
- V.03.0 → V.03.0.1: 문구와 명령 예시 수정
