# 알림·동기화 연락처 로그와 관리자 보고서

## 유지하는 동작
실제 수신자 선택·메일 본문·발송 반환값·동의·멱등키·재시도·원장 저장·
주소/영업상태 매칭을 바꾸지 않는다. 개인정보 마스킹은 진단 출력에만 적용한다.
발송 성공/실패·회원 유형/ID·발송 기록 ID·처리 건수는 남긴다.
오류 출력은 원문과 두 차례 URL 인코딩된 이메일/전화번호를 가리며,
연락처를 다시 노출할 수 있는 traceback 출력은 해당 발송 오류에서 사용하지 않는다.

## 관리자 연락처 보고서
기본 `python report_authority_match.py` 콘솔은 연락처를 숨기고 부서·지역·
매칭 성공/실패·폴백·집계를 그대로 표시한다.
기존 연락처 포함 보고가 필요한 권한 있는 CLI 사용자는
`python report_authority_match.py --contact-report authority-contacts.txt`로 선택한다.
출력은 `.local/private-reports/`의 새 파일에만 저장한다.
폴더0700·파일0600, 기존 파일 덮어쓰기·절대/상대 경로 탈출·심볼릭 링크를
거부한다. 이 폴더는 Git와 배포에서 제외하며 웹 다운로드 경로를 만들지 않는다.
이는 이미 DB에 접근 가능한 CLI 사용자의 기존 보고 기능이며 새로운
웹 사용자 권한을 부여하는 기능이 아니다.

## 검증과 운영 경계
가상 이메일·휴대폰·유선·국제/대표번호·인코딩 오류·발송 실패/예외와
기본/명시 보고서·파일 권한을 검사한다. 연락처 포함 본문/보고서의 원본
기능은 유지하고 기본 로그/콘솔의 유출만 막는 것을 확인한다.
실제 발송과 운영 DB·PG·배포는 실행하지 않는다.
개인정보 스캐너 결과와 전체 회귀 결과는 각각 별도로 보고하고,
경고·실패·격리 때문에 실행되지 못한 경로를 PASS로 표현하지 않는다.
Phase18은 기존 승인 대기 상태를 유지한다.

## 기존 보존 기준
원래 동결 기준 파일은 변경하지 않는다. 명시적으로 승인된 두 동기화 파일의
연락처 진단 변경에 한해 원래 해시와 승인된 정확한 해시를 별도 기록한다.
다른 파일 추가·범위 확대·기준 해시 변경·후속 소스 변경은 계속 차단하며,
기존 라우트/기능 보존 검사와 운영 승인 게이트는 그대로 유지한다.
