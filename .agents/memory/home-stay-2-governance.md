name: HOME & STAY 2.0 개편 경계
description: 사용자 확정 개편 방향과 운영자산 보존·검증·승인 경계
---

HOME & STAY 2.0은 소비자 단기임대 중심이지만 기존 숙박·부동산 데이터 기능을
삭제하거나 숙박 마스터를 전 건축물 DB로 덮어쓰지 않는다.
실제 숙박시설은 1박부터, 숙박시설 외는 7일부터다. Airbnb/농어촌/캠핑을
이름만으로 비숙박 7일 모델에 넣지 않는다. 숙박은 날짜별, 비숙박은 주·월 요금이며
확정예약의 가격은 스냅샷으로 보존한다.

**Why:** 사용자가 2026-10-10에 기존 운영자산 보존을 최우선으로 지정했고,
기존 플랫폼에는 실제 하루 예약이 가능한 숙박시설도 있음을 명시했다.

**How to apply:** 향후 개발은 저장소 Master Spec과 18단계 acceptance 기준을 먼저
읽는다. 테스트 실패·미구현 기준은 다음 단계 진행을 막는다. 운영 DB migration,
실제 PG/정산 활성화, 운영 배포는 개발 자동화와 분리해 별도 사용자 승인 필요.
‘머무는 곳을, 집처럼.’은 후보이며 운영 UI에 강제 적용하지 않는다.

사용자가 제공하는 Phase 번호와 저장소의 단계 번호/범위가 같다고 가정하지 않는다.
명시적 대응관계를 먼저 기록하고 요청한 범위를 넘는 단계는 시작하지 않는다.

**Why:** 사용자의 새 지시서는 기존 저장소 계획과 순서가 다를 수 있다고 명시했다.
설계에 후속 기능의 데이터 요건을 포함하는 것과 그 기능 구현·단계 시작은 다르다.

**How to apply:** 새 지시가 일부만 제공되면 나머지 순서를 추정하지 않는다.
고정 보존/회귀/승인 게이트를 유지하면서 현재 범위의 계약 검사만 연결한다.

단계 실행이 중단되거나 끝났을 때 사용자가 이를 모르도록 두지 않는다.
현재 사용자 Phase·RUNNING/PASS/FAIL/BLOCKED·완료 범위·검사결과·원격 저장·
차단 사유·다음 작업을 상태 기록과 종료 보고에 명시한다.

**Why:** 사용자가 “중단되었는데 모르고 있었네. 이러면 안되지”라고 재차 지시했다.

**How to apply:** 진행 전에 RUNNING을 남기고, 미해결 실패는 이유와 함께 BLOCKED로
표시한다. 승인된 범위 안에서 자동으로 해결·재검증한다. 완료 보고만으로 자동 진행을
종료하지 말고, 아래의 최신 연속 진행 지시를 따른다.

Work가 Phase 원문을 읽어 Replit에 작업 지시하고, 실제 결과를 확인한 후 다음
Phase를 지시하는 방식으로 18까지 연속 진행한다. PASS마다 사용자에게 재확인하지
않는다. 총괄지시서의 사용자 승인 Gate 또는 해결되지 않은 실패/명세·연결 차단에서만
중단하고 상태와 필요한 결정을 보고한다.

**Why:** 사용자가 2026-10-10에 이전 Phase 3 종료 제한을 해제하고,
“Work가 Phase 3 내용을 읽어 Replit에 작업 지시 → 결과 확인 → Phase 4 지시 → …”
방식으로 18까지 상호소통하며 계속 진행하도록 명시했다.

**How to apply:** Work의 실제 전달 경로와 Phase 원문을 확인하고 지시·구현·검증·결과
회신 근거를 남긴다. 외부 Work 연결이나 상시 실행기가 없으면 있다고 주장하지 않는다.
사용자 Phase와 저장소 단계의 번호 차이 및 미구현 선행 조건을 숨기지 않는다.
운영 DB·실제 PG·배포 승인, 미확정 법적·요금 정책은 이 연속 진행 지시로 승인된 것이 아니다.

Work는 Replit 내부의 총괄 지시·결과 검토 역할로 수행한다. 외부 Work 서비스 연동이
아니다. 사용자 원문의 순서는 로그인(4) → PC 메인(5) → 등록(6) → 가격/캘린더(7) →
검색/Super Map(8) → 상세/예약패널(9) → Booking(10) → 결제기반(11) →
운영자 대시보드(12) → 관심/채팅/알림/내예약(13) → FAQ/가이드/정책(14) →
관리자(15) → 모바일(16) → 통합검증(17) → Cutover/Open(18)이다.

**Why:** 사용자가 내부 Work 역할을 선택하고 사용자 총괄지시서 원문을 제공하며,
저장소 native 계획과 단계 번호가 다르므로 원문을 기준으로 진행하도록 명시했다.

**How to apply:** 사용자 순서로 지시·실제 구현·검증·검토를 기록하고 기존 native
영수증을 완료로 바꾸지 않는다. 사용자 18의 실제 Cutover/Open은 단순 준비와
다르므로 운영 승인 없이는 완료로 기록하지 않는다.
