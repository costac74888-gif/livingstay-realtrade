---
name: 모바일 패널 브라우저 테스트
description: 모바일 상세·지도 흐름을 실제 브라우저에서 안정적으로 재현할 때 지켜야 할 패널 상태 규칙
---

모바일 브라우저 테스트에서 검색 패널 토글을 무조건 클릭하지 말고, 현재 접힘 상태를 먼저 확인한 뒤 필요할 때만 연다.

**Why:** 건물 상세를 여는 경로에 따라 검색 패널의 기존 열린 상태가 유지된다. 연속 흐름에서 토글을 무조건 누르면 패널을 열려던 단계가 오히려 닫아 칩이 보이지 않는 간헐적 실패가 생긴다.

**How to apply:** 관심단지·최근조회처럼 접힌 검색 패널 안의 요소를 누르는 브라우저 테스트는 `collapsed` 상태를 확인하는 상태 기반 헬퍼를 사용한다. 지도 클릭 검사는 앱의 패널 토글로 먼저 패널을 닫는다. 뒤로가기는 이전 상세를 비동기로 다시 열 수 있으므로, 뒤로가기 완료를 기다리지 않은 채 다음 지도 검사를 시작하지 않는다.

여러 viewport를 검사할 때 새 브라우저 context가 서버/DB 저장 상태까지 초기화한다고
가정하지 않는다. 이전 viewport가 저장한 항목은 다음 viewport에서도 남아 있을 수 있다.

**Why:** SQL을 사용하는 등록 화면은 새 브라우저에서도 이전에 철회한 항목을 다시 열었다.
새 context만 만든 검사는 ‘새 등록’이 아니라 기존 철회 화면에서 입력하려다 실패했다.

**How to apply:** 초기 조회가 끝난 뒤 새 작업 액션을 명시적으로 사용하거나, 별도로
소유한 fixture 데이터를 초기화한다. 사용자 원장을 삭제해 검사 상태를 맞추지 않는다.
