---
name: GitHub 이력 보존 동기화
description: Git 인증과 연결 인증의 차이 및 게시 빈 커밋을 보존할 때 주의할 점
---

Git 전송 인증 실패를 기존 GitHub 연결의 인증 실패와 동일시하지 않는다. 대체 동기화에서도 원래 커밋 해시와 이력을 보존하고 원격 브랜치는 비강제로만 갱신한다.

**Why:** Git 명령은 인증 실패했지만 기존 GitHub 연결은 정상이며 쓰기 권한이 있었다. 게시 과정에서 생기는 빈 커밋을 Git Data API로 복원할 때 빈 tree 목록을 새로 만들면 422가 발생해, 원래 tree를 재사용해야 했다.

**How to apply:** 연결이 정상인데 Git만 실패하면 불필요한 재연결이나 토큰 조회를 하지 않는다. 승인된 대체 동기화는 blob·tree·commit 해시를 원본과 대조하고, 변경 파일이 없는 커밋도 생략하지 않는다. 갱신 전 원격 변경을 확인하고 force:false를 유지한다.

텍스트 변경은 tree 생성 요청의 inline UTF-8 content로 묶어 전송할 수 있다.

**Why:** 파일마다 blob 요청을 병렬 전송하면 기존 연결이 정상이어도 429 요청 제한이
발생할 수 있다. inline tree로 호출 수를 줄이면 원래 Git object 해시를 유지하면서
저장할 수 있으며, 이는 인증 오류나 재연결 필요를 의미하지 않는다.

**How to apply:** 원문 바이트가 UTF-8로 정확히 왕복하는지 확인한 경우에만 묶는다.
바이너리는 원래 바이트로 전송한다. tree/commit SHA 일치를 계속 검사하고, 429에는
제한된 대기·재시도를 적용한다. 실패 시 원격 ref를 바꾸거나 force로 우회하지 않는다.
