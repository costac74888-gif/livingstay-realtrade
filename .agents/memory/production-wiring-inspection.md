---
name: 운영 연결 객체 검사
description: fixture 파일 존재와 실제 운영 실행 연결을 구분하는 검사 원칙
---

가상 로그인·결제의 운영 유입은 파일 존재가 아니라 실제 생성 호출과 등록된
앱의 연결 객체를 기준으로 판정한다. 사용하지 않는 fixture import는 허용하고,
운영 경로를 바꾸는 경우 명시적 재검토가 필요하다.

**Why:** 개발 Preview는 의도적으로 가상 신원과 모의 결제를 결합한다. 해당
소스가 있다는 이유로 게시를 막으면 승인된 기존 운영 앱까지 차단한다.

**How to apply:** 게시 전에는 키가 제거된 환경과 소유 DB에서 운영 실행 명령을
검사하고, 성공을 실제 PG 검증이나 운영 활성화 승인으로 표현하지 않는다.

객체 그래프 검사는 방문 객체의 강한 참조를 유지하고, Flask의 요청 프록시와
작업공간 안에 설치된 외부 패키지를 무차별 탐색하지 않는다.

**Why:** 임시 dict의 ID가 재사용되면 나중 resolver를 방문했다고 오판한다.
요청 프록시를 컨텍스트 밖에서 접근하거나 외부 패키지를 프로젝트 코드로
취급하면 승인된 앱도 검사에 실패한다.

**How to apply:** 방문 상태에 객체 자체를 보존하고 실행 경계에서만 탐색한다.
역할 resolver는 별도의 익명 요청 컨텍스트에서 확인한다.
