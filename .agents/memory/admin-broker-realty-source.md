name: 관리자 입점부동산 기준
description: 브로커 표준데이터와 상권정보 캐시가 함께 존재할 때 관리자 화면·내보내기에 적용할 우선순위입니다.
---

관리자 건물마스터의 입점부동산 값은 주소 매칭된 브로커 표준데이터를 우선한다. 표준데이터 매칭이 전혀 없을 때만 기존 상권정보 캐시를 참고용 폴백으로 사용한다. 도로명 매칭 결과가 있으면 지번 매칭 결과를 합치지 않는다.

**Why:** 같은 열에서 화면·합계·엑셀이 서로 다른 출처의 수를 보이면 관리자가 데이터 신뢰성을 판단하기 어렵고, 도로명·지번 양쪽에 걸리는 동일 업소를 중복 집계할 위험이 있다.

**How to apply:** 입점부동산의 이름·건수·합계·내보내기 등 동일한 사용자 개념을 새로 추가하거나 변경할 때, 브로커 우선 및 도로명 우선 규칙을 함께 적용한다. Python 정규화가 필요한 계산값은 서버 정렬을 제공하지 않는다.

공공데이터포털 브로커 API의 현재 응답은 최상위 `header`·`body` 구조이며 별도 영업상태 필드를 주지 않는다. 이 목록은 개업 사무소 목록이므로, 새로 수집한 행은 `영업중`으로 저장한다. 상태 필드가 제공되는 응답 변형은 그 원본값을 우선한다.

**Why:** 이전 `response` 래퍼 전제는 실제 수집을 중단시켰고, 기존 레코드의 주소 정규화 키와 상태가 갱신되지 않았다. 이미 저장된 과거 레코드의 상태는 외부 원본을 재수집하기 전에는 추정하면 안 된다.

**How to apply:** API 응답 형태를 변경할 때 실제 최상위/래퍼 구조와 상태 기본값을 함께 회귀 테스트한다. 재수집은 저장된 도로명·지번 정규화 키도 다시 채워 주소 표기 편차 매칭을 복구한다.
