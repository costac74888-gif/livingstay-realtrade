---
name: 숙박 정부 CSV 8종 정책
description: 정기 갱신 정부 CSV의 고정 범위, 분류, 인허가·폐업 보존 원칙
---

정부 공공 CSV의 고정 범위는 관광숙박업, 관광펜션업, 농어촌민박업, 숙박업, 외국인관광도시민박업, 일반야영장업, 자동차야영장업, 한옥체험업 8종이다. 전문휴양업은 서비스 원장에서 제외한다. 정부가 원본을 갱신하면 먼저 개발 환경에 올려 검증하고, 승인된 변경 배치만 운영에 반영한다.

`문화_숙박업.csv`의 관광호텔·휴양콘도미니엄업은 원장에 보존하고 서비스 숙박분류 `관광숙박`에 포함한다. 건축물대장 건축물 용도 확정값은 별도 필드로 보존하며 이 분류만으로 덮어쓰지 않는다. 숙박업 기타는 원장에 보존하고 서비스 숙박분류는 `일반숙박`으로 통합하며, 업태 공백은 관리자 확인 대상으로 둔다.

동일 시설에 복수 인허가가 있으면 관리번호별 신고를 모두 보존하고 화면에도 우선 모두 표시한다. 휴업 자료는 삭제하지 않고 원장과 기본 영업목록에 `휴업` 상태로 표시하되 활성 영업 통계에서는 별도 제외한다. 폐업·취소 자료도 원장에 보존하되 기본 영업목록에서는 제외한다.

**Why:** 복수 인허가는 서로 다른 법정 신고일 수 있고 휴업·폐업 이력은 현재 상태와 변경 추적에 필요하다. 관광호텔·휴양콘도미니엄업은 관광숙박업 원본과 중복될 수 있지만 법정 신고별 기록을 잃지 않아야 한다. 전문휴양업은 이 서비스가 다루는 숙박 영업 원장의 범위에서 제외하기로 확정했다.

정책 변경 중·후 기존 모든 사용자 기능과 정상 운영 기능을 정지시키지 않으며, 완료 후 회귀가 없어야 한다. 문제가 발생하면 해당 배치나 경로만 격리하고 마지막 정상 상태로 즉시 복구할 수 있어야 한다.

**Why:** 데이터 정책 자체가 맞더라도 검색·상세·통계·매물·인증·동기화가 중단되거나 변경 완료 후 회귀가 남으면 서비스 관점에서는 실패다. 기능 무중단과 복구 가능성을 최상위 안전 기준으로 고정해야 단계적 전환 중 데이터 손실과 운영 공백을 막을 수 있다.

**How to apply:** 새 CSV importer·관리자 동기화·운영 승격·통계 변경 시 이 8종 범위와 보존 원칙을 공통으로 적용한다. 주소가 같다는 이유만으로 신고를 합치거나, 최신 파일에서 빠졌다는 이유만으로 상태 행을 물리 삭제하지 않는다. `관광숙박`·`일반숙박`은 서비스 숙박분류이며 건축물대장 `building_use_type`과 혼동하지 않는다. 운영 전환 대상 직접 동기화 버튼은 대체 경로가 검증되고 갱신 공백이 없을 때만 숨기지 않고 비활성화하여 `개발에서 동기화 중`을 표시한다. 기존 기능 기준선 테스트와 복구 경로가 통과되기 전에는 기존 운영 경로를 중단하지 않는다.

CSV 객실수 공란은 0실이나 삭제 지시가 아니다. 기존 허가번호의 운영 객실수는
CSV에 유효한 값이 있을 때만 갱신하고, 공란이면 기존 값을 보존한다. 신규 신고의
기재 객실수와 건물 마스터의 호실수도 별도 지표로 유지한다.

**Why:** 8종 CSV는 원본별 객실수 완성도와 집계 기준이 달라, staging 객실수
합계를 운영 원장에 전면 덮어쓰면 정상 호실이 대량 소실될 수 있다.

**How to apply:** 승인 dry-run에서 기존 운영 객실수, staging 기재 객실수,
신규 신고 기재 객실수를 분리 표시하고, 전면 대체 예상치는 제공하지 않는다.
