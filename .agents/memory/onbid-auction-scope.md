description: 공매 1차의 공개 범위, 기존 기능 보호, 재산유형과 입찰결과의 검증 원칙
---

공매 1차는 온비드 공공 API 자료의 사진·일반정보·원문 링크를 먼저 제공한다. 투자분석·체크리스트·현황조사는 2차이며, 메뉴와 범례 이름은 “공매”다.

**Why:** 사용자가 공적 공매 정보와 홈앤스테이 자체 분석의 도입 단계를 명시적으로 분리했다.

**How to apply:** 1차에 분석 기능이나 법원경매 수기 등록을 추가하지 않는다. 법원경매는 새 탭의 공식 검색 링크만 제공하고 대법원 사이트 크롤링·자동조회는 하지 않는다. 기존 캠핑 렌더링, 에어비앤비 분류 키, 건물 ID, 운영 DB 접속 비밀값은 변경하지 않는다.

온비드의 “수탁재산”은 “신탁공매”의 동의어로 취급하지 않는다. 공고기관과 공식 공고 근거로 신탁을 검증하고, 판정되지 않은 종류는 단정하지 않는다.

**Why:** 공식 API의 재산유형 코드에는 수탁재산이 있지만 신탁공매 전용 코드가 없다. 요청한 화면 분류와 공급자 분류를 그대로 일대일 매핑하면 오표시할 수 있다.

**How to apply:** 실제 목록·입찰·공고 응답으로 종류를 검증한 뒤 분류한다. 명세만 확인한 단계에서는 신탁 조회 가능 여부나 전국 물건 수를 확정하지 않는다.

입찰 마감·개찰 중·목록에서 사라짐만으로 유찰이나 낙찰을 확정하지 않는다. 비공개 입찰가격은 0원으로 바꾸지 않는다.

**Why:** 목록과 부동산 상세는 입찰 진행·예정 물건 중심이며, 최종결과와 별도의 마감·개찰 상태를 구분한다. 소실이나 미공개 값을 결과·가격으로 추정하면 공매 안내가 잘못된다.

**How to apply:** 종료 물건의 회차별 입찰 결과를 재조회하고, 검증된 최종 결과와 변경 시각을 기준으로 보존·지도 노출 정책을 적용한다. 공급자 연결 실패나 인증 거부는 0건 수집과 구분해 보고한다.

온비드 오류 30만으로 공통 인증키 자체가 잘못됐다고 결론 내리지 않는다. 승인된 다른 온비드 서비스에 같은 키로 호출해 서비스별 등록·권한 차이를 확인한다.

**Why:** 같은 키가 공고목록에서는 정상 응답하면서 부동산 물건목록·상세 등에서는 등록되지 않은 서비스키 오류를 반환하는 것을 확인했다. 공고목록 승인과 부동산 물건목록 승인은 별개다.

**How to apply:** 활용신청 화면의 정확한 서비스명을 확인하고 실제 필요한 서비스별로 호출한다. 승인 확인 과정에서 인증키 값이나 개인정보가 포함된 화면을 요청하지 않는다. 서비스별 승인·반영 문제를 키 교체나 네트워크 장애와 혼동하지 않는다.

온비드 목록의 총 건수는 물건 수가 아니라 입찰 조건·회차 행 수일 수 있다. 공개 물건 수는 물건관리번호로 중복 제거하고, 회차는 별도 이력으로 보존한다. 날짜의 2999년 값은 실제 입찰일이나 D-day로 사용하지 않는다.

**Why:** 실제 목록에서 호텔 하나가 여러 예정 회차로 반복되었고, 과거 물건의 입찰 일정에 2999년이 반환됐다. 원본 총계를 그대로 물건 수로 표시하거나 날짜를 기계적으로 해석하면 수량과 마감 안내가 잘못된다.

**How to apply:** 수집·보고 시 물건 수와 회차 수를 구분한다. 일정이 비정상적인 행은 원본을 보존하되 일정 미확인으로 처리하고, 유효한 날짜·상태가 확인된 진행·예정 건수와 섞지 않는다. 원장에 숙박시설로 묶인 생활숙박·모텔·펜션 등의 세분류는 별도 용도명 조회가 빈 응답이라는 이유만으로 전국 0건으로 단정하지 않는다.

회차 번호만으로 과거 개찰 결과를 현재 입찰에 연결하지 않는다. 공고가 바뀌면 같은 물건도 회차 번호를 다시 사용한다.

**Why:** 실제 입찰 중인 물건의 현재 1회차와 과거 공고의 1회차가 겹쳐, 과거 유찰·낙찰 결과가 현재 상태를 덮어쓰는 사례를 확인했다.

**How to apply:** 동일 입찰조건 식별자가 확인되거나 종료 일정과 실제 개찰일이 맞을 때만 결과를 확정한다. 이력도 공고·개찰일을 구분하고 현재 회차 강조는 번호 비교로 정하지 않는다.

새 공매 알림은 관심단지의 명시적 신청 이후 처음 등장한 물건에 한해 사이트 알림함으로 전달한다. 과거 초기 원장과 같은 물건의 후속 회차는 새 물건으로 통지하지 않는다.

**Why:** 기존 관심단지 기능을 재사용하되 초기 전국 원장 수집으로 과거 공매 알림이 한꺼번에 발생하거나 회차 수만큼 중복 알림이 생기는 것을 막아야 한다.

**How to apply:** 구독과 물건 최초 관측 시각을 비교하고 회원·물건별로 전달을 중복 방지한다. 알림 해제 또는 관심단지 삭제를 존중하며 이메일·SMS 발송으로 범위를 확대하지 않는다.

공매 목록의 정렬은 범위 슬라이더나 조건 카드 안의 별도 낮은순·높은순 버튼이 아니라 목록 헤더의 화살표 정렬로 제공한다. 조건 카드에는 지역·종류·상태·용도만 두고 선택 즉시 적용한다.

**Why:** 사용자는 슬라이더 제거와 오름·내림차순 정렬을 확정한 뒤, 참고 이미지에서 조건 카드의 정렬 행·요약·조건 적용 버튼을 삭제하고 목록 위 정렬 줄로 옮기도록 구체화했다.

**How to apply:** 입찰마감일·감정평가금액·최저입찰가격·유찰횟수·최신순을 클릭해 방향을 전환하고 같은 줄에서 페이지당 건수를 고른다. 최저입찰가격은 비율이 아닌 실제 금액 정렬이다. 숨은 최저가율 범위 제한으로 물건을 제외하지 않는다.

지도 범례의 공매 선택은 일반 숙박시설과 겹쳐 켜는 추가 레이어가 아니라 공매만 보는 배타적 선택이다.

**Why:** 사용자가 공매를 선택했는데 일반 숙박시설 집계가 함께 남은 화면을 보고 “공매선택시 공매만 나오게” 요청했다.

**How to apply:** 광역·지역 집계는 공매가 있는 지역의 공매 건수만, 확대 지도는 공매 물건만 표시한다. 다른 숙박 범례나 전체를 선택하면 공매 선택을 해제하고 기존 숙박 지도를 복원한다.
