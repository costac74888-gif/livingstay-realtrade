description: 공매 1차의 공개 범위, 기존 기능 보호, 재산유형과 입찰결과의 검증 원칙
---

공매 1차는 온비드 공공 API 자료의 사진·일반정보·원문 링크를 먼저 제공한다. 투자분석·체크리스트·현황조사는 2차이며, 메뉴와 범례 이름은 “공매”다.

**Why:** 사용자가 공적 공매 정보와 홈앤스테이 자체 분석의 도입 단계를 명시적으로 분리했다.

**How to apply:** 1차에 분석 기능이나 법원경매 수기 등록을 추가하지 않는다. 법원경매는 새 탭의 공식 검색 링크만 제공하고 대법원 사이트 크롤링·자동조회는 하지 않는다. 기존 캠핑 렌더링, 에어비앤비 분류 키, 건물 ID, 운영 DB 접속 비밀값은 변경하지 않는다.

온비드의 “수탁재산”은 “신탁공매”의 동의어로 취급하지 않는다. 공고기관과 공식 공고 근거로 신탁을 검증하고, 판정되지 않은 종류는 단정하지 않는다.

**Why:** 공식 API의 재산유형 코드에는 수탁재산이 있지만 신탁공매 전용 코드가 없다. 요청한 화면 분류와 공급자 분류를 그대로 일대일 매핑하면 오표시할 수 있다.

**How to apply:** 실제 목록·입찰·공고 응답으로 종류를 검증한 뒤 분류한다. 명세만 확인한 단계에서는 신탁 조회 가능 여부나 전국 물건 수를 확정하지 않는다.

입찰 마감·개찰 중·목록에서 사라짐만으로 유찰이나 낙찰을 확정하지 않는다. 비공개 입찰가격은 0원으로 바꾸지 않는다.

**Why:** 목록과 부동산 상세는 입찰 진행·예정 물건 중심이며, 최종결과와 별도의 마감·개찰 상태를 구분한다. 소실이나 미공개 값을 결과·가격으로 추정하면 공매 안내가 잘못된다.

**How to apply:** 종료 물건의 회차별 입찰 결과를 재조회하고, 검증된 최종 결과와 변경 시각을 기준으로 보존·지도 노출 정책을 적용한다. 공급자 연결 실패나 인증 거부는 0건 수집과 구분해 보고한다.
