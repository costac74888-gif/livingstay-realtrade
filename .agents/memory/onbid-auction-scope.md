description: 공매의 수집 용도·공개 범위와 온비드형 목록, 기존 기능 보호 및 입찰결과 검증 원칙
---

공매는 온비드 공공 API 자료의 사진·일반정보·원문 링크와 투자분석·체크리스트·현황조사를 기존 지도·건물 패널에 통합한다. 메뉴와 범례 이름은 “공매”, 건물 탭은 “공매정보”다.

**Why:** 사용자는 공적 정보와 자체 조사를 구분하되, 별도 상세 페이지 대신 기존 건물 상세 틀 안에서 함께 확인하는 구조를 확정했다.

**How to apply:** 공매 상세는 좌측 건물 패널, 조사 신청은 우측 드로어·모바일 전체화면 시트로 제공한다. 기존 상세·신청 주소는 지도 딥링크로 호환한다. 법원경매는 새 탭의 공식 검색 링크만 제공하고 자동조회는 하지 않는다. 기존 캠핑 렌더링, 에어비앤비 분류 키, 건물 ID, 운영 DB 접속 비밀값과 분석 3종 화면은 변경하지 않는다.

온비드의 “수탁재산”은 “신탁공매”의 동의어로 취급하지 않는다. 공고기관과 공식 공고 근거로 신탁을 검증하고, 판정되지 않은 종류는 단정하지 않는다.

**Why:** 공식 API의 재산유형 코드에는 수탁재산이 있지만 신탁공매 전용 코드가 없다. 요청한 화면 분류와 공급자 분류를 그대로 일대일 매핑하면 오표시할 수 있다.

**How to apply:** 실제 목록·입찰·공고 응답으로 종류를 검증한 뒤 분류한다. 명세만 확인한 단계에서는 신탁 조회 가능 여부나 전국 물건 수를 확정하지 않는다.

입찰 마감·개찰 중·목록에서 사라짐만으로 유찰이나 낙찰을 확정하지 않는다. 비공개 입찰가격은 0원으로 바꾸지 않는다.

**Why:** 목록과 부동산 상세는 입찰 진행·예정 물건 중심이며, 최종결과와 별도의 마감·개찰 상태를 구분한다. 소실이나 미공개 값을 결과·가격으로 추정하면 공매 안내가 잘못된다.

**How to apply:** 종료 물건의 회차별 입찰 결과를 재조회하고, 검증된 최종 결과와 변경 시각을 기준으로 보존·지도 노출 정책을 적용한다. 공급자 연결 실패나 인증 거부는 0건 수집과 구분해 보고한다.

온비드 오류 30만으로 공통 인증키 자체가 잘못됐다고 결론 내리지 않는다. 승인된 다른 온비드 서비스에 같은 키로 호출해 서비스별 등록·권한 차이를 확인한다.

**Why:** 같은 키가 공고목록에서는 정상 응답하면서 부동산 물건목록·상세 등에서는 등록되지 않은 서비스키 오류를 반환하는 것을 확인했다. 공고목록 승인과 부동산 물건목록 승인은 별개다.

**How to apply:** 활용신청 화면의 정확한 서비스명을 확인하고 실제 필요한 서비스별로 호출한다. 승인 확인 과정에서 인증키 값이나 개인정보가 포함된 화면을 요청하지 않는다. 서비스별 승인·반영 문제를 키 교체나 네트워크 장애와 혼동하지 않는다.

온비드 목록의 총 건수는 물건 수가 아니라 입찰 조건·회차 행 수일 수 있다. 공개 물건 수는 물건관리번호로 중복 제거하고, 회차는 별도 이력으로 보존한다. 날짜의 2999년 값은 실제 입찰일이나 D-day로 사용하지 않는다.

**Why:** 실제 목록에서 호텔 하나가 여러 예정 회차로 반복되었고, 과거 물건의 입찰 일정에 2999년이 반환됐다. 원본 총계를 그대로 물건 수로 표시하거나 날짜를 기계적으로 해석하면 수량과 마감 안내가 잘못된다.

**How to apply:** 수집·보고 시 물건 수와 회차 수를 구분한다. 일정이 비정상적인 행은 원본을 보존하되 일정 미확인으로 처리하고, 유효한 날짜·상태가 확인된 진행·예정 건수와 섞지 않는다. 원장에 숙박시설로 묶인 생활숙박·모텔·펜션 등의 세분류는 별도 용도명 조회가 빈 응답이라는 이유만으로 전국 0건으로 단정하지 않는다.

회차 번호만으로 과거 개찰 결과를 현재 입찰에 연결하지 않는다. 공고가 바뀌면 같은 물건도 회차 번호를 다시 사용한다.

**Why:** 실제 입찰 중인 물건의 현재 1회차와 과거 공고의 1회차가 겹쳐, 과거 유찰·낙찰 결과가 현재 상태를 덮어쓰는 사례를 확인했다.

**How to apply:** 동일 입찰조건 식별자가 확인되거나 종료 일정과 실제 개찰일이 맞을 때만 결과를 확정한다. 이력도 공고·개찰일을 구분하고 현재 회차 강조는 번호 비교로 정하지 않는다.

새 공매 알림은 관심단지의 명시적 신청 이후 처음 등장한 물건에 한해 사이트 알림함으로 전달한다. 과거 초기 원장과 같은 물건의 후속 회차는 새 물건으로 통지하지 않는다.

**Why:** 기존 관심단지 기능을 재사용하되 초기 전국 원장 수집으로 과거 공매 알림이 한꺼번에 발생하거나 회차 수만큼 중복 알림이 생기는 것을 막아야 한다.

**How to apply:** 구독과 물건 최초 관측 시각을 비교하고 회원·물건별로 전달을 중복 방지한다. 알림 해제 또는 관심단지 삭제를 존중하며 이메일·SMS 발송으로 범위를 확대하지 않는다.

오피스텔은 숙박 공매 수집 대상이 아니다. 이미 저장됐더라도 공매 목록·지도·상세·신규 조사 신청에서 제외한다.

**Why:** 사용자가 “오피스텔은 수집용도가 아님/모두 제거할것”이라고 명시했다. 숙박시설 응답에 섞인 오피스텔과 과거 저장분도 같은 기준으로 차단해야 한다.

**How to apply:** 수집 용도에서 제외하고 응답·저장 경계에서도 검사한다. 과거 신청 이력 보호를 위해 원장을 물리 삭제하지 말고 공개 경계를 닫는다. 일반 건물 데이터의 용도 분류는 바꾸지 않는다.

공매 목록은 사용자가 첨부한 온비드처럼 사진·물건정보·회차·입찰기간·감정가/최저입찰가를 비교하는 목록이다.

**Why:** 사용자가 이전 한줄 표 요구를 온비드 참고 이미지 형식으로 대체하고, 물건정보 상세 이동과 상단 정렬 메뉴 우측의 페이지 개수 선택을 명시했다.

**How to apply:** 실제 원본 사진·관리번호·용도·재산종류·처분방식만 표시하고 미공개 가격을 0원으로 만들지 않는다. 페이지당 10·20·50·100개 선택은 상단 정렬줄 맨 오른쪽에 배치한다. 물건정보는 기존 공매정보 상세 딥링크로 연결한다. 모바일에서도 가로 넘침 없이 정보를 읽을 수 있어야 한다.

공매 물건이 기존 건물에 연결되지 않아도 상세 화면은 부동산정보·운영정보·공매정보의 공통 틀을 유지한다.

**Why:** 사용자는 건물 미연결 물건을 클릭했을 때 공매정보만 나오는 화면을 잘못된 동작으로 지적하고 세 정보 화면이 나와야 정상이라고 명시했다. 특정 호텔에만 적용하지 말고 다른 모든 공매 물건에도 기존 상세 연결을 적용하도록 재차 요청했다.

**How to apply:** 건물 연결 여부는 데이터 확보 범위를 결정할 뿐 상세 화면의 탭 구조를 축소하는 기준이 아니다. 미확인 정보는 확인된 공매 원본과 구분하고, 건물 없음과 기존 건물 미매칭을 같은 사실로 단정하지 않는다.

공매 사진은 세 정보 탭 위에 공통으로 표시하고, 공매목록에서 들어온 상세의 뒤로가기는 사용자가 클릭했던 목록 상태로 복귀한다.

**Why:** 사용자가 사진의 상단 배치와 부동산정보·운영정보 다음의 공매정보 버튼을 명시했고, 뒤로가기가 초기 공매목록으로 돌아가는 것을 잘못된 동작으로 지적했다.

**How to apply:** 건물 연결 유무와 관계없이 같은 위계를 유지한다. 상세에서 목록으로 돌아갈 때 지역·용도·상태·정렬·페이지·페이지당 개수와 스크롤 위치를 보존한다.

지도 범례의 공매 선택은 일반 숙박시설과 겹쳐 켜는 추가 레이어가 아니라 공매만 보는 배타적 선택이다.

**Why:** 사용자가 공매를 선택했는데 일반 숙박시설 집계가 함께 남은 화면을 보고 “공매선택시 공매만 나오게” 요청했다.

**How to apply:** 광역·지역 집계는 공매 건수만 표시한다. 확대 지도는 공매 박스와 그 공매에 매칭된 건물 포인트만 함께 제공하며, 박스와 포인트는 서로 다른 탭을 여는 독립 클릭 대상이다. 다른 숙박 범례나 전체를 선택하면 공매 선택을 해제하고 기존 숙박 지도를 복원한다.

같은 도로명주소에 여러 건물 원장이 있어도 서로 다른 지번의 대장·운영정보를 합치지 않는다. 확실한 연결을 읽기에서 확인할 수 있다면 외부 상세 수집 완료를 기다리게 하지 않는다.

**Why:** 실제 호텔 공매에서 정확한 지번의 원장은 대장 정보가 부족했고, 같은 도로명에 정보가 풍부한 다른 지번 원장이 함께 있었다. 도로명 중복만 보고 연결을 포기하거나 풍부한 원장을 임의로 선택하면 기존 정보가 숨겨지거나 다른 건물의 정보가 나타난다. 목록 수집만 완료된 원장은 API 한도로 상세 보강이 늦어질 수 있다.

**How to apply:** 정규 도로명·지번 후보의 유일한 교집합으로 대조하며, 충돌·복수 필지는 보류한다. 공식 물건명에 완전한 주소가 있으면 정확한 주소 키만 대조하고 상호 유사도는 쓰지 않는다. 조회 결과와 다음 수집의 연결 기준을 일치시키고 운영 원장의 ID·대장 값을 임의로 바꾸지 않는다.
