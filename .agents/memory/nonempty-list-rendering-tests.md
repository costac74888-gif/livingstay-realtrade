---
name: 목록 렌더링 검사
description: 예외를 화면 오류로 처리하는 목록의 브라우저 검사 성공 기준
---
목록 검사는 비어 있지 않은 응답으로 실제 행과 카드를 확인해야 한다. 빈 목록이 정상 표시되거나 pageerror가 없다는 사실만으로 렌더링 성공을 판정하지 않는다.

**Why:** 목록 로더가 렌더러의 예외를 잡아 오류 문구로 표시하면 pageerror는 발생하지 않는다. 빈 응답 검사에서는 렌더러가 실행되지 않아 운영의 정상 데이터에서만 터지는 오류를 놓칠 수 있다.

**How to apply:** 각 거래 대상·게시 방식·공개범위의 비어 있지 않은 표본으로 PC·모바일 행과 카드 수, 오류 문구 부재를 검사한다. 원본뿐 아니라 배포용 압축 스크립트도 실제 공개 응답으로 확인하되 테스트가 운영 데이터나 외부 알림을 변경하지 않게 한다.

미장착 Blueprint의 test client 성공은 HTML 자산 URL이나 폼의 실제 동작을 증명하지 않는다.

**Why:** API 검사가 통과해도 잘못된 스크립트 URL 때문에 컨트롤러가 로딩되지 않고 폼이 네이티브 GET으로 제출될 수 있다.

**How to apply:** 격리 HTTP에서 실제 브라우저로 스크립트 로딩·비어 있지 않은 선택 목록·입력부터 완료까지를 검사한다. 운영 앱을 부팅하거나 인증을 우회하지 않는다.
