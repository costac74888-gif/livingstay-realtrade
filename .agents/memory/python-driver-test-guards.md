name: Python·DB 드라이버 검사 경계
description: 네이티브 인수·fail-open·자식 의존 경로·UNIX 지문 비교 주의사항
---

Python 검사 가드는 네이티브 DB 드라이버까지 감싸되 고수준 연결 함수와 C 드라이버의 인수 계약을 동일하게 취급하지 않는다. psycopg2의 cursor_factory는 DSN 항목이 아니며 C 연결 함수로 그대로 넘기지 않는다.

**Why:** 고수준 함수에서 유효한 인수가 DSN 파서와 네이티브 호출에서는 거부된다. 잘못된 가드의 오류를 앱 스키마 오류로 해석하면 원인 진단이 어긋난다.

**How to apply:** 연결 옵션과 Python factory를 분리하고 실제 로컬 PostgreSQL 연결로 검사한다. 연결 가드 설치 실패를 실제 DB 접근으로 폴백하지 않는다.

sitecustomize에서 일반 Exception을 던지는 것은 실행 중단 보장이 아니다. Python은 오류를 출력한 뒤 애플리케이션을 계속 실행할 수 있다.

**Why:** 격리 capability가 없을 때 가드가 무시되면 검사 코드가 정상 환경의 DB 설정으로 진입할 위험이 있다.

**How to apply:** capability 검증 실패는 interpreter를 즉시 종료시키고, 후속 코드가 실행되지 않는 별도 subprocess 검사를 유지한다.

UNIX socket로 연결하는 개발·운영 비교 fixture는 서로 다른 DB 이름을 사용해야 한다. 현재 실제 연결 지문에서 UNIX 연결의 서버 주소·포트는 NULL이므로 별도 클러스터라도 같은 DB 이름이면 같은 대상으로 보인다.

**Why:** 서로 다른 owned PostgreSQL 클러스터 두 개를 만들었지만 둘 다 postgres DB로 연결하자 운영 쓰기 금지 게이트가 정상적으로 차단했다.

**How to apply:** 비교용 DB도 owned 임시 클러스터에 만들고 다른 DB명을 명시한다. 실제 운영 URL을 주입하거나 안전 게이트를 해제하지 않는다.

격리 환경을 다시 만드는 자식 Python에는 실행 파일 경로만으로 설치된 패키지 경로가 보장되지 않는다. 비밀값이 없는 런타임 의존 경로를 함께 전달하고 단독 실행과 상위 격리 실행기 안의 실행을 모두 확인한다.

**Why:** 정리된 상위 실행 환경은 원래 셸의 Python 설치 환경을 그대로 보존하지 않는다. 가드 의존성을 찾지 못하면 시작 단계에서 실패한다.

**How to apply:** 환경 전체를 복사하지 않는다. 안전한 패키지 경로만 보존하며, 시작 오류가 DB 소유권 오류인지 의존성 오류인지 분리한다.
