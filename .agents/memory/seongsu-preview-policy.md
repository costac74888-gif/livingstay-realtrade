description: 목업 기반 가상 매물 체험 우선순위와 운영/개발 분리 원칙
---

반복 체험 검사는 고정된 미래 날짜가 비어 있다고 가정하지 않는다.

**Why:** Preview 재시작 전에는 이전 검사에서 승인·결제한 가상 예약도 남아
같은 날짜의 재예약을 정상적으로 차단한다. 이를 상품 오류로 오판하면 안 된다.

**How to apply:** 현재 캘린더에서 빈 기간을 먼저 확인하고 새 가상 예약을 만든다.
기존 예약을 삭제하거나 재고 보호를 해제해 검사를 통과시키지 않는다.
실제 매물이 없어도 사용자가 당초 목업에 맞춘 개발 Preview에서 직접 비교·예약을 테스트할 수 있도록 성수동1가·2가의 가상 매물을 최소 12개 유지한다.
사진·가격·면적·인원·편의시설·날짜와 서로 다른 가상 위치를 채우고 숙박 일별, 비숙박 주·달력 월, 마감 날짜를 포함한다.
매매·영업권 양도·공매는 독립 레이어의 가상 항목으로만 제공한다.

개발 메인 배경은 기존 HOME & STAY의 실제 카카오 지도이며 기존 우측 세로
도구와 동작을 재사용한다. 가상 물건은 실제 지도 위의 테스트 좌표로 표시하며,
좌표 도식·새 지도·가짜 타일로 대체하지 않는다.

소비자 메인은 단기대여만 표시한다. 기존 시설·매매·영업권 양도·공매는
소비자 지도에서 제외하고, 시설·운영 관리 지도에서 실제 연결 가능한 시설과
네 매물 유형을 독립적으로 표시한다. 시설과 매물은 서로 연결하지 않는다.

**Why:** 사용자가 최종 지도 분리를 지정했다. 이전 혼합 메인 지도 결정은
이 요구로 대체되었다. 시설·운영 관리 모드는 화면 맥락이지 소유권 부여가 아니다.

**How to apply:** 격리 원장·결제·발송 경계는 유지하며 공개 브라우저 지도
식별자와 읽기 전용 SDK만 예외로 연결한다. 연결 실패는 구체적인 원인과
필요 조치를 밝히고, 도식으로 성공을 가장하지 않는다.

Preview의 앱 글자는 최소 16px이며 검은색, 배경은 흰색과 연한 올리브색이다.
검은 글자 강제 적용 시 안내·보조 링크의 기존 어두운 배경도 함께 점검한다.

**Why:** 주요 버튼의 색 검사만으로는 안내 화면의 금색·어두운 링크 배경을 발견하지 못했다.

**How to apply:** 주요 화면뿐 아니라 체험 안내와 보조 동작도 실제 캡처로 확인하며,
검정 글자가 어두운 배경에 남지 않도록 배경과 텍스트 대비를 함께 검증한다.

누락된 실제 시설이나 좌표를 가상 시설로 채우지 않는다. 확인하지 않은 전체
시설 수는 검증된 수치와 명확히 구분한다.

시설 검증용 공개 필드 스냅샷은 가상 예약 원장과 출처를 분리한다.
운영 읽기 전용 원본에서 가져왔더라도 실시간 운영 연결·운영 계정 연결로 표시하지 않는다.
마스터 전체, 분류된 시설, 좌표 보유 시설은 서로 다른 집계 기준이다.

**Why:** 개발 시설 수와 운영 마스터 수가 달랐고, 공개 시설 자료를 확보해도
실제 회원·예약·결제 연결은 별도로 미완료일 수 있다.

**How to apply:** 공개 필드만 내보내고 수집 전후 원본 지문과 집계를 대조한다.
누락 좌표는 목록에 보존하며 전 페이지 중복·누락 및 전국 클러스터 합계를 검증한다.
고객·소유자·금융 원장은 복사하지 않고 생성된 QA 자료는 Git·배포에서 제외한다.

**Why:** 사용자가 “너무 작은 글자를 절대 사용하지 말것”을 반복했다.
큰 글자로 바꾼 뒤에도 기존 공통 스타일의 고정 높이와 지도 패널 배치가
조작부를 덮을 수 있었다.

**How to apply:** 작은 화면 문제를 글자를 줄여 해결하지 않는다. 날짜 조건은
접을 수 있게 하되 그대로 유지하고, 실제 브라우저에서 글자 크기뿐 아니라
첫 화면 내 범례·수량·클릭 가능 영역까지 확인한다. 제공자 지도 타일과 원본
로고 자체를 새로 그리거나 다른 이미지로 대체하지 않는다.

**Why:** 사용자가 2026-10-11에 “매물이 없더라도 테스트매물을 여러 개 … 성수동 기준으로”를 추가하며, 목업 Preview의 직접 체험을 최우선으로 명시했다.

**How to apply:** 이후 목업·통합 단계에서도 빈 목록으로 돌아가지 않게 한다. 테스트용/가상 공간 이미지/실재 및 법적 운영 확인 아님을 명확히 표시하고 실제 연락처·소유자·사건·영업신고를 가져오지 않는다. 운영 데이터·숙박 통계·실제 결제·발송·정산과 혼합하지 않는다. PC·모바일 주소와 체험 순서·계정 제공 방식·미완료 범위를 함께 보고한다.

가상 데이터 표시·사진·정확한 가상 좌표·모의 결제 버튼은 소유한 격리 Preview가 서버에서 부여한 권한으로만 활성화한다. 일반 공유 HTML에 데모 활성 플래그를 고정하지 않는다.

**Why:** 공유 템플릿은 일반/비공개 화면과 모바일 shell에도 재사용된다. 화면 스타일만으로 가상 데이터 공개나 결제 성공의 근거를 만들면 안 된다.

**How to apply:** 일반 화면은 기존 사진·위치 비공개 계약을 유지하고 서버의 격리 확인 없이 데모 기능을 활성화하지 않는다. 모의 결제는 사용자 동의 후 서명된 owned provider 이벤트를 원장에 반영하고, 토스 키 보유와 실제 토스 테스트 API 연결을 구분한다. 재시작 시 초기화·체험자 간 공유된 가상 계정이라는 한계도 안내한다.

기준요금·날짜 안내 같은 Preview UI 작업은 기존 가격 엔진을 변경하지 않는다.
월은 입실일 기념일 기준이며 월·주 조합의 최저가 계산을 그대로 사용한다.
기준요금과 실제 선택기간 총액은 별개이며, 추천 날짜도 실제 엔진으로 확인한다.

**Why:** 사용자가 2026-10-11에 UI 개선 범위를 지정하면서 가격 엔진 수정 금지를 명시했다. 표시를 맞추기 위해 계산을 바꾸거나 유효하지 않은 견적을 만들어서는 안 된다.

**How to apply:** 새로운 요금 표시나 기간 선택 도우미도 공개 권한과 기존 견적 경로를 유지한다. 엔진이 지원하지 않는 견적은 명시적으로 비어 있는 상태로 남기고, 운영·스키마·키·배포 작업으로 확대하지 않는다.
