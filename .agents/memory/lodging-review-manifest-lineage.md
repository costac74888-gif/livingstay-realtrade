---
name: 수동검토 manifest 계보
description: 숙박 운영 승격의 수동검토 결정을 여러 번 순차 처리할 때 지켜야 할 버전 계보 원칙
---

수동검토 결정으로 생기는 manifest는 하나의 최신 자식으로만 이어지는 선형
계보여야 한다. 한 건만 해결한 자식은 남은 검토행을 그대로 보존할 수 있지만,
모든 검토행이 해결되기 전에는 승인과 dry-run을 허용하지 않는다.

**Why:** 여러 관리자가 오래된 부모 화면에서 각기 다른 행을 해결하면 서로 다른
자식 분기가 모두 승인 가능한 상태로 발전할 수 있다. 반대로 자식 생성 시 남은
검토행을 금지하면 검토 대상이 여러 건인 manifest는 첫 결정조차 저장할 수 없다.

**How to apply:** 검토 결정은 제출된 부모를 잠근 상태에서 기존 자식 여부를 확인하고,
이미 자식이 있으면 최신 manifest를 다시 불러오게 한다. 새 자식의 미해결 건수는
실제 payload에서 다시 집계하고, 승인·dry-run 경계에서 0인지 별도로 검증한다.
같은 staging 원본을 다시 승격할 때는 최신 배치의 `review_rows` 숫자만 보지 말고,
적용 완료 manifest의 전체 부모 계보에 해당 원본 행의 감사결정이 있는지 확인한다.
이미 적용된 결정은 다시 묻지 않되, 결정되지 않은 행은 계속 차단한다.
