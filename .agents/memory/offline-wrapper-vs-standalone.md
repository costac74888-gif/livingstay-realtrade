---
name: 오프라인 실행기와 단독 CI 명령
description: 전체 검사의 주입 환경에서 통과해도 등록된 단독 명령에서는 실패할 수 있다는 검증 범위 원칙
---

전체 오프라인 실행기 통과만으로 등록된 단독 CI 명령의 통과를 추정하지 않는다. 두 진입 환경의 차이도 확인한다.

검토 지문으로 묶인 검사 파일을 수정하면 현재 검사 등록 지문도 함께 검토한다.
과거 승인·실행 기록은 원래 지문을 보존한다.

**Why:** 채팅 검사의 대기 조건만 고쳐도 기존 등록 지문과 달라져
독립 게이트 검사들이 이를 미검토 검사로 거부했다.

**How to apply:** assertion·격리 권한이 유지된 diff를 확인하고 현재 등록 지문만
갱신한다. 지문 비교를 해제하거나 역사적 승인 기록을 새 지문으로 덮어쓰지 않는다.

합쳐진 최신 소스에서 끝점 계약이 바뀌었다면 이전 성공 기록도 다시 확인한다. 합성 payload 검사만으로 실제 앱 응답의 계약을 증명하지 않는다.

**Why:** 감싸는 실행기의 경로 주입 덕분에 전체 스모크가 통과했지만, 단독 스모크에서는 임시 작업공간의 중첩 빌드 검사가 프로젝트 모듈을 찾지 못한 일이 있었다. 제품 화면 회귀도 공급자 인증 오류도 아니었다. 별도로 합성 계약 검사가 통과했어도 병합 후 실제 끝점의 호환 응답이 달라 필수 검사가 실패했다.

**How to apply:** 실제 등록 명령을 그대로도 실행한다. 작업 디렉터리·자식 import 경로·안전 플래그의 상속 차이를 확인하고, 통과하도록 검사를 삭제하거나 감싸기 환경을 몰래 전제로 만들지 않는다. 끝점 계약은 소유 테스트 DB에 연결한 실제 앱 응답으로 검증하고, 전체 수집의 장기 모의 처리가 영향을 줄 수 있으면 새 프로세스를 사용한다.
