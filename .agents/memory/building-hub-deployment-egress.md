---

워크스페이스에서는 건축HUB 호스트 연결이 정상이어도 Replit 배포 환경에서는 `apis.data.go.kr:443` 연결 타임아웃이 반복될 수 있다. 또한 연결 가능한 환경에서도 특정 지번만 503을 반복하는 사례가 있다.

**Why:** 단순 재시도만 하면 지속 실패 지번이 매 실행의 앞부분을 다시 차지해 정상 지번 진행까지 막고, 배포 환경의 전체 연결 장애와 개별 지번 장애를 구분하기 어렵다.

**How to apply:** 지속 실패 지번은 완료로 기록하지 말고 시간 제한 대기열로 격리해 뒤의 정상 행을 처리한다. 연결 오류가 연속되면 실행을 실패 종료하지 말고 냉각 대기 후 남은 대상을 자동 계속한다. 배포 환경에서 장시간 전체 연결이 막히면 재시도 횟수만 늘리지 말고 워크스페이스 실행 또는 별도 한국 egress 경로를 검토한다.

온비드도 배포 환경의 목록 조회가 재시도 끝에 실패했지만, 작업공간에서 운영 DB를 대상으로 동일한 수집기를 실행하면 정상적으로 원장을 확보할 수 있었다.

**Why:** 개발 화면 검사가 통과해도 운영 원장이 확보된 것은 아니다. 운영 수집 실패로 테이블이 비어 있으면 화면은 오류가 아니라 정상적인 0건 응답을 표시한다.

**How to apply:** 목록 0건은 먼저 운영 API·운영 원장·수집 상태를 대조한다. 복구는 운영 마스터 기준으로 온비드 원본을 재수집하며, 개발 원장이나 개발 건물 연결 ID를 그대로 복사하지 않는다. 환경별 실패 이유를 보존하고 배포 환경의 자동수집 복구 여부는 별도로 확인한다.

중계 도입 범위는 건축HUB 건축물대장과 지정된 실거래 4종뿐이다. 모든 전환은 기본 OFF이며 직접 호출 자동 폴백을 추가하지 않는다. 실제 공공 API 시험과 대량 수집 실행은 별도 사용자 승인 전에는 금지한다.

**Why:** 2026-10-05 최종 연동 요청에서 이전 건축HUB·온비드 검토보다 적용 범위를 좁혔고, 기존 데이터·스키마·예약과 이미 성공하는 API를 보존하도록 명시했다.

**How to apply:** 과거 온비드 중계 계획을 활성화 승인으로 해석하지 않는다. 허용 목록 확대나 실제 조회는 새 승인을 받는다. DB 무변경 조건으로 선택한 중계 상태 기록은 실행 환경별 관측이며, 웹과 별도 예약 배치의 전역 공유 이력처럼 보고하지 않는다.

중계의 `RELAY_FORBIDDEN`은 클라이언트 결함으로 단정하지 않고, 별도로 관리되는 서버의 서비스 허용 정책·토큰 용도도 확인한다.

**Why:** 사용자가 중계 서버에 RTMS 허용이 없었다고 확인했고, 서버 허용을 추가한 뒤 클라이언트 코드 변경 없이 동일한 실거래 batch 요청이 정상 응답했다.

**How to apply:** 권한 거절을 없애려고 토큰 용도를 바꾸거나 직접 호출 폴백을 추가하지 않는다. 서버 정책과 클라이언트 허용 목록은 별도 관리 대상이며, 한 서비스의 성공을 다른 서비스·용도나 운영 배포 성공으로 확대 해석하지 않는다.

운영 중계 전환은 토큰·URL 준비 → 세 스위치 OFF로 첫 재게시 → 웹 건축HUB 활성화 후 재게시 → 운영 점검·안정화 → 실거래 활성화 순서로 진행한다.

**Why:** 사용자가 단계 순서를 중요 조건으로 지정했다. 사전 실호출이 성공해도 첫 재게시 전에 스위치를 켜면 코드 배포와 전송 경로 전환이 동시에 일어나 문제 구분이 어려워진다.

**How to apply:** 첫 OFF 재게시 성공 확인 전에는 ON 설정을 미리 적용하지 않는다. Scheduled는 별도 게시 설정을 확인하고, 문제가 생기면 전체 스위치를 OFF로 바꿔 재게시한다. 같은 실행 환경의 서비스 스위치는 realtime/batch를 따로 활성화하지 못한다.

중계 활성화 스위치 세 개는 Secrets에서만 관리한다. 일반 실행 워크플로에 오프라인 검사 환경을 남기지 않으며, 오프라인 검사는 별도 명령으로 수행한다.

**Why:** 사용자가 같은 이름의 저장소 설정과 Secrets가 겹치지 않도록 단일 관리 경로를 지정했고, 검사 설정이 일반 실행 명령에 남은 것을 바로잡도록 요청했다.

**How to apply:** `.replit`의 운영 일반 환경 설정에는 중계 URL만 둔다. 세 스위치를 일반 환경 설정이나 실행 명령에 중복 추가하지 않는다. 검사 후 일반 실행 명령은 원래대로 복구한다.
