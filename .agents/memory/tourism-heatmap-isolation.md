---
name: 관광 데이터랩 열지도 격리
description: 한국관광 데이터랩 원본을 기존 서비스 통계와 분리해 사용하는 원칙
---

한국관광 데이터랩에서 내려받은 방문자·관광소비·고캠핑 자료는 지역 열지도와 원본 검증을 위한 참고 데이터로만 사용한다. 검증되지 않은 값으로 기존 숙박·캠핑 통계의 합계, 신고업체·사이트 수, 신고율을 대체하거나 보정하지 않는다.

**Why:** 고캠핑 약 10만 사이트처럼 공개 API 및 현재 운영 원장과 큰 차이가 나는 값은 정보공개청구 원자료를 받아 범위와 산식을 검증해야 한다.

**How to apply:** 관광 데이터는 별도 저장소·API로 격리하고, 통계 반영은 출처 범위와 중복 제거 기준이 별도로 확정된 뒤 명시적 승인을 받아 진행한다.

같은 `source_period`라도 재다운로드 파일이 공존할 수 있으므로, 관광 데이터 조회는 최신 적재 파일 1개를 먼저 고른 뒤 그 `source_file` 안에서만 집계한다. 검색순위의 순위값은 전국 순위이므로 지역별 TOP N 조회에 전국 TOP20 상한을 재사용하지 않는다.

**Why:** 기간만으로 묶으면 같은 기간의 구·신 파일이 섞여 수치가 비결정적이 되고, 전국 순위 상한을 지역 상세에 적용하면 정상 데이터가 있어도 인기 관광지가 빈 목록으로 보인다.

**How to apply:** 관광 통계별 최신 파일을 적재시각과 파일명으로 결정적으로 선택한다. 전국 레이어만 전국 순위 상한을 적용하고, 지역 상세는 해당 지역 행 전체를 순위순으로 제한한다.

`지역별 관광지 검색순위`는 보통 공항·쇼핑몰 등을 포함하는 일반 관광지 원본이지만, 데이터랩은 숙박 필터 내보내기에도 이 일반 파일명을 사용할 수 있다. 전체 유효행의 중분류가 숙박이고 숙박 순위 필수 열이 모두 있을 때만 숙박 전용으로 판정한다. 숙박 순위의 건물 연결은 같은 정규화 시도·시군구 안에서 이름 후보가 하나뿐일 때만 허용한다.

**Why:** 2026-09-05 실제 숙박 필터 CSV 500행이 모두 숙박이면서 파일명은 `지역별_관광지_검색순위`였다. 반대로 파일명만으로 승격하면 비숙박 장소가 건물 순위에 섞이고, 전국 이름-only 매칭은 동명 호텔을 다른 지역 건물에 잘못 연결한다.

**How to apply:** 명시적 숙박 파일명 또는 전체 행의 숙박 카테고리 계약으로 유형을 결정하고, 혼합 카테고리는 일반 순위로 유지한다. 건물명 완전 일치를 우선하고, 충분히 긴 포함 일치도 후보가 유일할 때만 사용하며 모호하면 미매칭으로 남긴다.

관광 데이터랩 ZIP의 개발 DB 적용은 운영 DB로 자동 승격되지 않는다. 공개 API가 정상인데 운영 목록만 비면 환경별 `stat_type` 행 수를 먼저 비교하고, 전체 DB 병합 대신 필요한 원본 구성원만 같은 `source_file` 계보로 운영에 멱등 적용한다.

**Why:** 개발에는 방문객 급증 내·외국인 원본이 있었지만 운영에는 해당 두 유형이 0행이어서 공개 화면만 빈 목록으로 보인 사례가 있었다.

**How to apply:** 적용 전 운영을 읽기 전용으로 확인하고, 원본 ZIP에서 필요한 CSV만 같은 바깥 ZIP 이름으로 분리해 드라이런 수량을 검증한다. 적용 후 운영 행 수와 공개 API의 TOP N·좌표 매칭을 모두 대조한다.
