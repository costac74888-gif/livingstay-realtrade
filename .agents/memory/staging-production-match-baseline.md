---
name: Staging 매칭 기준선
description: 개발 staging의 주소 매칭 결과를 운영 반영 판단에 사용할 때 지켜야 할 기준선 원칙
---

개발 DB의 건물 마스터만으로 계산한 staging 주소 매칭률을 운영 매칭률로
해석하지 않는다. 운영 반영 검증은 운영 원장의 허가번호 집합과 기존 유효
건물 연결을 읽기 전용 기준선으로 먼저 비교하고, 신규 허가번호와 실제
주소 변경분만 다시 매칭한다.

**Why:** 개발과 운영의 수집·백필 진행도가 다르면 운영에 이미 존재하는 건물이
개발에는 없을 수 있어, 정상적인 기존 연결이 대량 미연결처럼 보인다.

**How to apply:** 정부 원본 staging 승인 전 환경별 원장 건수, 허가번호 차집합,
기존 연결 건물 수와 지도 좌표 건물 수를 분리 검산한다. 기존 허가번호의 유효한
연결은 보존하고 전체 초기화·전면 재매칭을 기본값으로 삼지 않는다.
승인 manifest도 개발 원장의 `diff_kind`만으로 만들지 말고 운영 허가번호 차집합을
반드시 포함한다. 보류 행은 누락하지 말고 수동검토 대상으로 manifest에 남긴다.
manifest의 중복 허가번호는 생성·dry-run·반영 모두에서 차단하고, 수동검토 행은
행별 해결 기록이 생기기 전까지 승인과 운영 반영을 허용하지 않는다.
운영에 이미 존재하는 허가번호는 개발 `diff_kind`가 `new`여도 운영 상태 분류가
다르면 상태 변경 대상으로 포함한다. 단, 이 예외를 일반 필드 갱신까지 넓히면
환경 차이로 대량 덮어쓰기가 생길 수 있으므로 상태 변경에만 적용한다.
