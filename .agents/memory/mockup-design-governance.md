description: 공개 경쟁사 원본 벤치마킹, 최신 색상과 사전 운영 검증의 경계
---

최신 지시가 아래 과거 승인보다 우선한다. 흰 바탕을 유지하고 주·월 단기대여는
파랑, 1박 숙박은 Airbnb 빨강을 사용하며 올리브·머스타드·금색은 제거한다.
삼삼엠투·Airbnb의 현재 공개 PC/모바일 화면을 실제 방문하고, 기능별로 참고 원본과
URL·관찰일·캡처·선정 이유를 기록한다. 로그인 뒤 화면은 열지 못했으면
NOT_OBSERVED로 표시하며 경쟁사 로고·사진·후기·전용 코드·미확인 라이선스 폰트는 복제하지 않는다.
과거의 검정 16px 일괄 덮어쓰기보다 관찰한 공개 화면의 실제 정보 밀도와 글꼴 위계를 우선한다.

**Why:** 사용자가 기존 승인 색상을 명시적으로 철회하고 실제 원본에 근거한 재구축을
요청했다. 과거 비교표의 채택 설명과 기능 PASS는 최신 시각적 일치의 증거가 아니다.

**How to apply:** 아래 과거 목업·올리브·16px·대표 시안 승인 대기 요구를 최신 요청에
적용하지 않는다. 개발 사전 운영 완성까지 독립적으로 진행하되 기존 원장·서비스·경로와
역사적 검수 자산은 보존하고, 운영 DB 변경·게시·실결제·실정산은 하지 않는다.
문서 예제 토스 키와 실제 상점 테스트 키를 구별하고, 가상 원장 PASS를 실제 계정·결제 검증으로 표시하지 않는다.

실제 네이티브 화면의 computed style을 검증해야 한다. 기존 응답 후처리
어댑터가 새 공유 스킨보다 늦게 과거 테마를 추가할 수 있다.

**Why:** 시안은 파랑/빨강인데 실제 버튼과 상속 변수는 올리브로 남았다.
가격 색상이나 CSS 원문만 확인하면 이 경합을 놓친다.

**How to apply:** 실제 버튼·요금·HOME & STAY 생성 지도 마커를 함께 대조하며
공급자 지도 UI와 구분한다. 원본 스타일 보존과 최종 실행 색상 검증은 별개다.

사용자가 제공한 목업은 디자인 구현 기준이다. 단계별 기능 요구로 바뀌더라도
화면 구성·정보 위계·색상·글꼴·여백·카드·배지·로고 방향을 임의 스타일로 대체하지 않는다.
확인된 참고 자료와 최종 승인본은 구분하며, 미확인 글꼴·사진·최종본을 승인된 것으로
추정하지 않는다.

**Why:** 사용자가 “당초 목업대로 하라고 해”라고 반복 지시했다. 목업 요구가
기능 중심 단계 지시·검수에 연결되지 않아 별도 스타일이 구현됐으며,
사용자는 이를 명시적으로 수정하도록 요구했다.

**How to apply:** 후속 화면 작업은 실제 참고 이미지와 원문을 먼저 열고,
확정된 2.0 제품 구조와 충돌하는 부분만 최소 조정한다. 조정 이유·남은 차이를
문서에 기록하고 PC·모바일 실제 화면과 대조한다. 기능검사 PASS를 디자인 일치
근거로 대신하지 않으며, 사진 공개·정확 위치 보호와 실제 결제 승인 경계를 유지한다.

실행 프리뷰 통합 요청은 별도 갤러리·정적 캡처 제공으로 대체하지 않는다.
화면 ID 수를 독립 페이지 수로 표시하지 않고, 디자인 반영·화면 검수와
실제 계정·운영 원장·결제 연결 완료를 각각 구분한다.

모바일 검수는 넘침·글자 크기만 확인한 자동 PASS로 완료 처리하지 않는다.
첫 화면에 검색과 실제 목록이 보이는지, 메뉴가 화면을 과도하게 차지하지 않는지,
지도 도구·팝업 닫기가 다른 영역에 가리지 않는지 실제 화면과 조작으로 확인한다.
브라우저의 모바일 폭 검사를 물리 휴대폰 실기 검증으로 표현하지 않는다.

**Why:** 2026-10-12 사용자가 실제 모바일 화면의 과도한 메뉴·검색 높이와 목록 가림을
지적하며 부분 반영 상태를 인정하고 모바일까지 완전히 반영·검수하라고 재차 요구했다.

**How to apply:** 자동 결과와 대표 화면 육안 확인·메뉴 조작 증거를 함께 제출하고,
모바일 폭·태블릿 폭·PC 폭과 물리 기기 확인 여부를 명시한다.

**Why:** 2026-10-12 사용자가 246개 시안을 실제 소비자·임대인·관리자 진입에
반영하되 기존 기능을 보존하고, 미완료 실계정·결제를 디자인 완료와 분리하라고 요구했다.

**How to apply:** 후속 디자인 통합·전달은 현재 실행 서버의 실제 경로를 검증하고,
별칭·탭·팝업·상태를 명시한다. 기존 기능 컨트롤러를 시안의 하드코딩 데이터로
대체하지 않으며, 운영 배포 승인 없이 개발 반영을 운영 게시로 해석하지 않는다.

2026-10-11 사용자가 다시 보낸 3화면(지도 검색·상세·운영자) 이미지가 현재 디자인
기준이다. 기본 바탕은 흰색이며, 작은 목업 글자를 그대로 축소 재현하지 않고
읽을 수 있는 크기로 키운다.

**Why:** 사용자가 “목업을 다시 보내주니 최대한 이대로 디자인 하도록 하고
기본바탕은 흰색으로 하고 글자도 작지 않게 해”라고 명시했다.

**How to apply:** 이미지의 흰색 바탕, 사진 목록, 지도·상세·운영 화면 위계를
유지한다. 색상은 아래의 최신 지시를 우선한다. 예전 도식/다른 첨부 이미지를 이 기준보다 우선하지 않는다.

파란 글자는 검정으로 변경한다. 사용자가 제공한 흑백 가로형 HOME & STAY 로고와
정사각형 앱 로고를 원본으로 사용하며 임의 로고로 대체하지 않는다.
기존 HOME & STAY 웹페이지를 기준으로 삼삼엠투·직방 단기임대의 사용성을 적극
벤치마킹하되 경쟁 서비스와 구분되는 브랜드색을 사용한다.
2026-10-11 사용자가 딥 올리브 #596044를 메인색으로 승인했다.

**Why:** 사용자가 2026-10-11 원본 로고 두 종을 제공하며 “파란글자를 모두 검정으로”
바꾸고 기존 웹페이지 참고와 경쟁 서비스 벤치마킹을 명시했다.
이후 딥 올리브 적용 질문에 해당 추천안을 명시적으로 선택했다.

**How to apply:** 로고 원본 형태를 보존하고, 검색·필터·사진·요금 정보의 위계는
벤치마킹하되 경쟁사의 로고·사진을 복제하지 않는다. 승인된 메인색은 주요 버튼·
선택 상태에 적용하고 로고·검정 글자·경고색·지도 공급자 표기는 유지한다.
원본 로고의 크기·비율을 표준 규격으로 추정하지 않고 실제 파일로 확인한다.
2026-10-12 전체 시안 요청에서는 요금만 색상 예외로 두고, 버튼·직접 div·footer를
포함한 글자는 검정 16px 이상으로 통일한다. 어두운 버튼의 흰 글자라는 이전 해석보다
이 최신 지시를 우선하며, 검정 글자가 읽히는 밝은 버튼 바탕을 사용한다.

**Why:** 사용자가 전체 화면 디자인 범위에서 검정 글자와 최소 크기, 주거/숙박 요금
색상 예외를 함께 명시했다.

**How to apply:** 공통 텍스트뿐 아니라 직접 텍스트 노드와 입력 컨트롤도 확인한다.
지도 공급자 UI와 제공 조건은 자체 텍스트 검사·스타일 변경 범위와 구분한다.

기존 기능 보존은 파일을 남기는 것으로 판정하지 않는다. 실거래·숙박 분류·
검색·매물·관심단지·운영·관리·상담의 기존 경로와 새 Preview의 실제 연결을
별도로 확인하고, 가상 확장 기능을 기존 기능의 대체 또는 통합 완료로 표시하지 않는다.

**Why:** 사용자가 2026-10-11에 “기존 홈앤스테이 기능을 최대한 살려서” 하라는
지시를 재차 강조하고, 기존 서비스 기능과 원본 목업의 보존·연결을 요구했다.

**How to apply:** 보존표에는 유지/확장/미연결을 분리하고 실제 계정·원장·
서비스 경계를 검증하기 전에는 전체 통합 완료를 주장하지 않는다.

2.0 화면 개편은 별도 클릭 가능한 디자인 Preview를 먼저 제출하고, 사용자의
개별 수정·승인 이후에 기존 기능 화면으로 반영한다. 디자인 시안의 화면 선택은
로그인·관리자 권한 선택이 아니며 실제 예약·결제·발송으로 이어지지 않는다.

**Why:** 사용자가 화면 디자인을 먼저 만들어 주면 이후 개별 수정사항을
전달하겠다고 명시했다. 기존 기능 검사 완료를 디자인 승인으로 간주하지 않는다.

**How to apply:** 사용자·상세·임대인·관리자 화면을 PC 1440px와 모바일 390px로
확인하고 실제 캡처를 제출한다. 공개 경쟁사 DOM/computed CSS 확인과 소스 재사용
허가는 구분하며, 라이선스가 미확인인 경쟁사 코드·사진·전용 폰트는 복제하지 않는다.
