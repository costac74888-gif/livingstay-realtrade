description: 고캠핑 basedList의 상태·사이트 수·호출량을 해석할 때 지켜야 할 외부 API 규칙
---

고캠핑 `basedList`의 운영상태 원본은 `manageSttus`이며, 활성 상태 `운영`은 서비스의 `영업/정상`으로 정규화한다. 캠핑 사이트 수는 일반·자동차·글램핑·카라반·개인카라반 사이트 수의 합계이고 숙박 객실 수와 섞지 않는다. dry-run도 실제 외부 API 호출을 소비하므로 일일 호출량에는 포함한다.

**Why:** 2026-08-30 실제 응답에서 `manageSttus`, 단일 주소 `addr1`, 유형별 사이트 수 필드를 확인했다. 다른 상태 필드명을 가정하면 모든 캠핑장이 비활성으로 처리되고, dry-run을 카운트하지 않으면 공식 일일 한도를 초과할 수 있다.

**How to apply:** 고캠핑 데이터를 다룰 때 사이트 수와 객실 수를 분리하고, dry-run도 공식 API 호출 한도를 소비하는 실행으로 취급한다.

`imageList`는 사진이 없는 캠핑장에서 `response.body.items`를 객체나 배열이 아니라 빈 문자열로 반환할 수 있다. 이를 오류나 빈 덮어쓰기로 처리하지 말고 정상적인 사진 없음으로 해석하며, 기존 대표사진·다중사진 값은 보존한다. `basedList`와 `imageList`는 같은 일일 호출 버킷을 사용한다.

**Why:** 2026-09-05 운영 백필에서 빈 문자열 `items` 응답이 반복 확인됐다. 오류로만 처리하면 불필요한 재시도가 생기고, 빈 배열로 저장하면 이전 사진을 잃을 수 있다.

**How to apply:** 이미지 응답 파서는 `None`, 빈 배열, 공백뿐인 문자열을 사진 없음으로 허용한다. 모든 실제 이미지 호출은 목록 호출과 같은 원자적 일일 한도에서 예약한 뒤 실행한다.

캠핑 통계의 공통 열 제목은 추후 `건물수(시설수)`로 바꾼다. 캠핑 신고율은 정상영업 신고시설 기준 100%로 표시하고, 사이트수 필드 확보율은 관리자 품질지표로만 둔다.

**Why:** 건축물 없는 야영장이 많아 건물수·호실수 기준은 부적절하며, 신고 CSV에서 온 정상영업 시설을 사이트수 누락 때문에 낮은 신고율로 보이면 의미가 왜곡된다.

**How to apply:** 일반·자동차야영장 CSV/XLSX의 `좌표정보(X/Y)`를 수집한다. 값은 WGS84 경위도가 아닌 한국 TM 투영좌표이므로 좌표계를 검증해 변환한 뒤, 대장 미매칭 시설도 별도 카카오 마커로 표시한다.
