---
name: Git 기준 범위 검사와 자동 체크포인트
description: HEAD 상대 변경 검사를 장기 보존/원본 보존의 증거로 오해하지 않는다
---

HEAD와 현재 파일의 차이를 검사하는 범위 제한 테스트는 저장/자동 체크포인트 뒤
기준이 이동한다. 통과를 이전 요청 이후의 모든 변경이 없다는 증거로 사용하지 않는다.

**Why:** 개발 Preview 실행 명령처럼 현재 요청이 허용한 변경도 이전 작업의
미커밋 범위 검사에서 실패했고, 저장 뒤에는 같은 변경이 HEAD에 포함된다.
테스트를 약화하지 않더라도 검사가 증명하는 범위를 구분해야 한다.

**How to apply:** 원래 assertion과 실패 로그를 보존한다. 현재 요청의 명시적
기준 commit 대비 실제 diff를 별도로 검토하고, 동결 manifest/라우트 보존 검사도
독립 실행한다. 승인된 변경을 저장한 뒤의 통과를 운영 준비 완료로 확대 해석하지 않는다.
