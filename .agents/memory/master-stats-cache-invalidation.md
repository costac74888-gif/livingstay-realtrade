---
name: 마스터 통계 캐시 무효화
description: 별도 수집 워크플로와 앱 워커 사이에서 통계 캐시 신선도를 유지하는 규칙
---

마스터 통계 캐시는 앱 프로세스 메모리에 있으므로, 건물·주소매칭·숙박신고·실거래처럼 그 입력을 변경하는 **모든** 별도 수집 프로세스와 앱 수정 경로는 원본 변경 커밋 뒤 공유 `app_meta` 무효화 신호를 갱신해야 한다.

**Why:** Gunicorn 워커와 수집 워크플로는 메모리를 공유하지 않는다. 프로세스 안에서만 캐시를 비워도 다른 워커에는 전달되지 않아 TTL 동안 이전 통계가 제공될 수 있다.

**How to apply:** 새 배치나 기존 수집기의 변경 범위를 검토할 때, 마스터 통계의 입력을 실제로 수정하는 성공 경로마다 DB 커밋 후 무효화 표식 갱신을 넣는다. 여러 단위로 커밋하는 작업은 마지막 성공 시점 하나가 아니라 **각 원본 변경 커밋 직후** 신호를 남겨, 뒤 단계의 오류가 이미 저장된 데이터를 가리지 않게 한다. 표식 기록 실패가 이미 커밋된 원본 수집을 실패로 바꾸지는 않되, 기록이 빠지면 다음 앱 요청에서 재계산이 일어나지 않는다는 점을 확인한다.

만료·무효화된 캐시에 이미 성공한 섹션 값이 있으면 공개 통계 API는 그 값을 stale로 즉시 반환하고, 워커별 단일 백그라운드 재검증만 예약한다. 캐시가 비어 있을 때만 요청에서 동기 재계산한다. 재계산의 일부 섹션이 실패하면 직전 성공 데이터는 유지하되 섹션 상태는 오류로 기록한다.

**Why:** 사용자 요청을 긴 집계가 끝날 때까지 대기시키지 않으면서, 일시적인 원본·DB 장애가 직전 정상 통계를 빈 화면이나 오류로 바꾸지 않게 한다.

**How to apply:** 마스터 통계 API나 새로운 섹션을 추가할 때 stale 값(빈 배열도 유효)을 폴백으로 버리지 말고 공통 캐시 경로를 거치게 한다. stale 재검증 예약은 같은 워커에서 중복 실행되지 않아야 하며, 스레드 시작·실행 실패 뒤에는 다음 요청 또는 폴링이 다시 예약할 수 있어야 한다. 브라우저 메모리 캐시를 쓰는 탭이 서버 무효화를 확인하려고 주기 폴링한다면, 그 폴링 요청은 브라우저 TTL을 우회해 실제 네트워크 요청을 보내야 한다.
