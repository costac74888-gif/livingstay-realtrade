---
name: 분석 슬라이더 입력 경계
description: 임대·운영 분석의 URL 복원 상한과 월세 중심 고정 원칙
---

공유 링크·탭 간 전달·직접입력은 화면 표시 직전이 아닌 **값을 수용하기 전** 같은 절대 상한으로 검증한다. 잘못된 공유 URL 수치는 버리고 해당 파라미터만 지우며, 유효한 건물 기준값이 있으면 잘못된 매입가·월세만 안전한 기본값으로 다시 채운다.

**Why:** 상한 없는 과거 링크가 비정상적으로 큰 금액을 슬라이더에 복원해 사용자가 범위를 조작할 수 없었다. 나중에 화면만 잘라도 계산·공유 상태는 이미 오염된다.

**How to apply:** 신규 시나리오 공급 경로가 생기면 복원 지점에서 상한 검증을 선행하고, 계산에 쓰는 정확한 수치와 슬라이더 표시 수치를 구별한다.

월세·비교월세의 범위 중심은 건물·면적·탭 진입이나 직접입력 확인처럼 명시된 재설정 시점에만 바꾼다. 슬라이더 드래그나 매입가 변경은 현재값을 바꿀 수 있어도 중심을 재설정하지 않는다.

**Why:** 매수가 변경 때마다 현재 월세를 새 중심으로 삼으면 월세 최대를 반복 선택할 때 범위가 계단식으로 계속 증가한다.

**How to apply:** 종속 슬라이더 갱신과 범위 중심 갱신을 별도 이벤트로 취급하고, 반복 드래그·매수가 변경 회귀 테스트를 유지한다.

임대·운영 분석의 한 가로바를 움직일 때 다른 가로바의 값과 범위는 유지한다. 특히 대출금은 매수가와 독립적으로 0~40억까지 허용한다.

**Why:** 사용자가 가로바 간 자동 영향을 없애달라고 요청했으며, 대출금이 5억 눈금에서 매수가 때문에 잘리는 것을 보고 매수가 이내 조건 폐지를 명시했다.

**How to apply:** 슬라이더·직접입력·공유 링크 복원에서 대출금을 같은 절대 상한으로만 검증한다. 매수가를 낮춰도 대출금은 변경하지 않으며, 실투자금이 0 이하라면 계산불가로 표시하는 기존 계산 처리를 유지한다.

숙박운영 ADR 바는 1만~200만원을 허용하되, 1만~10만원 구간에 바 길이의 약 1/3을 배정한다. 실제 분석값과 공유값은 원 단위로 유지하고 바에서만 1만원 단위로 선택한다.

**Why:** 200만원 상한의 균등 눈금에서는 저가 ADR 1만~10만원이 휴대폰 화면의 짧은 구간에 몰려 조절하기 어려웠다.

**How to apply:** ADR 눈금은 10만원을 고정 전환점으로 하는 두 구간으로 매핑한다. 직접 입력·원본 업로드·URL 복원의 정확한 금액을 바 위치로 반올림하더라도 원래 분석값을 바꾸지 않는다.

임대 매수가·대출금 가로바는 각자의 최솟값부터 5억원까지를 눈금 길이의 약 1/3에 배정하고, 나머지 구간을 각자의 기존 절대 상한까지 배정한다. 매수가의 표시 최솟값은 시세 기반으로 변하고 대출금 눈금은 0~40억원에 고정한다.

**Why:** 50억·40억의 전체 구간을 균등하게 배치하면 5억원 이하를 조절하기 어렵다는 사용자 요청이 있었다.

**How to apply:** 눈금 위치만 금액으로 왕복 변환하며 시나리오·URL·계산은 만원 단위 실제 값을 유지한다. 직접입력의 정확한 금액을 눈금 단위로 덮어쓰지 않고 다른 슬라이더 독립성을 유지한다.
