---
name: 주간 이메일 공개 데이터 원칙
description: 주간 이메일의 공개 숫자와 별도 30일 랭킹의 범위, 빈 상태, 관리자 검수본 원칙
---

주간 이메일의 공통 DataLab 숫자는 운영 홈페이지가 사용하는 공개 API 응답을 그대로 요약하고 임의의 대체값을 만들지 않는다. 단, 사용자가 명시적으로 승인한 최근 30일 관심단지 거래와 신고가·거래량 TOP5는 홈페이지의 7일 랭킹과 기간이 달라 거래 원장에서 별도 조회하고, 기간을 명시한다. 이 30일 랭킹을 7일 공개 랭킹으로 대체하지 않는다. 뉴스는 신뢰할 수 있는 공식 원문 링크를 검증한 경우에만 표시하며, 공급원에 기사 없음·장애 시 가짜 기사나 오래된 기사를 채우지 않는다. 기능 소개는 기존 관리자 저장값을 사용한다.

**Why:** 사용자가 30일 통일을 승인했는데 홈페이지의 7일 랭킹을 그대로 재사용하면 표시 기간과 실제 계산이 달라진다. 반대로 다른 공통 지표의 임의 재계산·fallback은 운영 화면과 다른 숫자를 만들 수 있다. 검증되지 않은 뉴스는 신뢰성을 해친다.

**How to apply:** 주간 발송 경로의 기간·SQL·공통 통계·관리자 사본을 바꿀 때 적용한다. 새로운 비교 수치는 기간과 산식을 명시적으로 합의하지 않았다면 공개 API를 따른다. 승인된 30일 거래 랭킹은 실제 거래 원장을 읽되 자료가 없으면 empty state를 표시한다. 수신자 원장 SQL은 실제 DB rollback 검사로 확인하고 자식 프로세스 stdout/stderr는 실행별 로그에 보존한다.

회원이 자신의 메일로 주간메일 테스트를 요청하면 관리자 공통 사본이나 가상 데이터를 대신 보내지 않는다. 지정한 회원의 실제 운영 계정 데이터를 읽어 관심단지(거래가 없는 단지의 이름 포함), 진행 중인 매물·매수의뢰, 활성 기능 소개를 모두 넣고 수신자는 그 계정의 등록 이메일로만 제한한다. 테스트 발송은 정기 발송 원장과 분리해 표시한다.

**Why:** 가상 거래·의뢰로 만든 검수본은 실제 회원 상태를 확인할 수 없고, 거래가 없는 단지를 숫자로만 묶거나 기능 소개를 빼면 승인한 메일과 다르게 보인다.

**How to apply:** 계정별 테스트 메일을 보낼 때 수신자 일치·운영 원장·섹션별 실제 표시를 발송 전에 확인하고, 예시를 쓸 경우에는 사용자 요청 범위를 먼저 구분한다.

거래가 없는 관심단지가 많으면 건물마다 표 행을 만들지 않고, 거래된 단지 다음에 이름을 쉼표로 이어 쓰는 짧은 문단으로 표시한다. 뉴스는 국내 숙박 전문 저널과 국내 공식 출처의 숙박 관련 원문만 최대 3건 표시한다. 기사 제목·게시일·출처·원문 HTTPS 링크가 유효해야 하며, 확보한 기사가 3건 미만이면 지어내거나 해외 기사로 채우지 않는다.

**Why:** 회원 관심단지가 많을 때 미거래 단지별 표 행은 메일을 지나치게 길게 만든다. 해외 소식으로 5줄을 채우는 것보다 국내 숙박업에 맞는 기사 3건을 명확한 출처와 함께 보여주는 것을 사용자가 선택했다.

**How to apply:** 뉴스 출처·기간·표시 수를 변경하거나 실제 회원 테스트 메일을 발송할 때 원문 링크와 국내 숙박 관련성을 확인한다.

관리자 수동 전체 발송은 같은 주 대표 계정의 개인화 테스트 메일이 발송 서비스에 접수된 후에만 가능하며, 전체 발송을 시작하면 테스트 승인을 소진한다. 테스트 발송은 주간 회원 발송 원장을 차지하지 않는다.

**Why:** 공통 관리자 사본은 회원별 관심단지·의뢰 내용 검증을 대신하지 못한다. 한 번의 테스트로 여러 차례 전체 발송을 허용하면 바뀐 메일 내용이 검수 없이 재발송될 수 있다. 사용자가 대표 계정의 개인화 테스트 메일을 정상 수신했다고 확인했다.

**How to apply:** 관리자 발송 버튼·주간 발송 상태를 바꿀 때 서버 쪽에서도 테스트 성공·동일 주차·승인 소진을 확인한다. 수신 거부와 기존 중복 방지 원장은 계속 유지한다.
